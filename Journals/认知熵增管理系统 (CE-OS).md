

#### 一、 诊断：状态识别与熵值判定
将大脑视为一个处理系统，其状态由**能量（Energy）** 与 **熵值（Entropy/杂乱度）** 决定。

| 状态关键词 | 系统表征 | 判定本质 |
| :--- | :--- | :--- |
| **Loud (吵闹)** | 反复反刍、情绪卡点 | **高熵值**：认知资源被无效背景任务占用。 |
| **Racing (狂奔)** | 想法跳跃、停不下来 | **过载**：执行频率过快，缺乏制动机制。 |
| **Empty (真空)** | 提不起劲、无动力 | **系统挂起**：缺乏引导输入，处于“冷启动”困难。 |
| **Tired (低电)** | 低级错误、无法聚焦 | **低能量**：硬件过热或电池见底，需物理干预。 |
| **Sharp (高亮)** | 逻辑清晰、深度聚焦 | **低熵高能**：系统处于最优执行窗口。 |

#### 二、 策略：按状态执行（Action Protocol）

- **1. [Loud] → 认知卸载 (Offloading)**
    - **操作：** 快速书写 `mind-dump.md`。
    - **逻辑：** 将内存中的“后台进程”强制写入硬盘（纸/文档），通过视觉化降低系统熵值。
- **2. [Empty] → 语义激活 (Priming)**
    - **操作：** 5-10分钟的**被动式深度输入**。读一篇已收藏的硬核长文，不求产出。
    - **逻辑：** 通过高质量的外部语义信号“点火”，重新激活认知引擎。
- **3. [Racing] → 物理制动 (Grounding)**
    - **操作：** 去信息化的**空间位移**（如步行）。禁止一切数字信号输入。
    - **逻辑：** 强制降低处理频率，让“思维碎屑”沉淀。
- **4. [Tired] → 硬件维护 (Hardware Refresh)**
    - **操作：** NSDR（非睡眠深度休息）或 20min 睡眠。若不允许，则只处理**线性机械任务**。
    - **逻辑：** 承认硬件极限，通过降低复杂度来减少对系统残余能量的损耗。
- **5. [Sharp] → 核心打击 (Core Impact)**
    - **操作：** 锁定“关键第二步”。关闭所有通知，直接进入项目最难部分。
    - **逻辑：** 这种状态是稀缺资源，严禁用于处理回邮件、打扫等低价值任务。

#### 三、 演化：趋势监控与上游优化
记录每日占比，通过数据倒逼“上游管理”：
- **高频 Loud ( >50% )：** 诊断为“未处理焦虑”。**上游策略：** 建立每日“担忧清单”，在特定时间集中处理。
- **高频 Tired：** 诊断为“生理冗余不足”。**上游策略：** 强制调整睡眠窗口或简化日程。
- **短促 Sharp：** 诊断为“认知干扰过剩”。**上游策略：** 采用“信息斋戒”，上午不触碰任何信息流。
