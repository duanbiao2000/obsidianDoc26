## Key Entities

- **System Design Capability Framework (系统设计能力框架)**
    - **Type:** Conceptual Model / Learning Roadmap
    - **Role:** Central subject of the document. Defines a four-stage progression for mastering system design skills.
    - **Wiki Status:** New concept. While related to [[Staff Engineer]] and general engineering practices, this specific structured framework does not exist in the wiki index.
- **DDIA (Designing Data-Intensive Applications)**
    - **Type:** Book / Reference Resource
    - **Role:** Primary learning resource cited for foundational concepts (CAP theorem, ACID/BASE, caching, databases).
    - **Wiki Status:** Not explicitly listed as a standalone entity, but its concepts (CAP, ACID) are present. The book itself should be added as a key resource.
- **Key System Design Concepts**
    - **CAP Theorem:** Trade-off between Consistency, Availability, Partition tolerance.
    - **ACID vs BASE:** Strong consistency vs. eventual consistency models.
    - **Load Balancing & Caching Strategies:** Core infrastructure components.
    - **Message Queues:** For async communication, decoupling, and peak shaving.
    - **Design Patterns:** Creational, Structural, Behavioral patterns with their specific trade-offs.
    - **Wiki Status:** These concepts likely already exist or can be linked to existing entries like [[ETL管道]], [[Redis]], [[Kafka]], etc., but the *framework* connecting them is new.
- **Classic Systems for Study**
    - **Entities:** Google Search, Twitter Timeline, YouTube, Uber, Instagram.
    - **Role:** Case studies used in Stage 2 to understand real-world design decisions.
    - **Wiki Status:** Peripheral. No specific pages for these case studies exist, though tools like [[Kafka]] and [[Redis]] are mentioned elsewhere.
- **AI Collaboration in System Design**
    - **Type:** Methodology/Workflow
    - **Role:** Describes a modern workflow where AI assists in initial solution generation and code scaffolding, while the engineer focuses on constraints, evaluation, and critical decision-making.
    - **Wiki Status:** Relates to [[AI 编码代理核心循环]] and [[Context Engineering]], but applies it specifically to high-level architectural design rather than just coding tasks.

## Key Concepts

- **System Design Capability Definition**
    - **Definition:** Defined not by tool knowledge, but by four core abilities: Problem Decomposition, Trade-off Decision Making, Abstract Thinking, and Global Vision.
    - **Why it matters:** Shifts the focus from "how to use tools" to "how to think architecturally."
    - **Wiki Status:** New definition. Contrasts with superficial views of system design.
- **Four-Stage Learning Progression**
    - **Definition:** A timeline-based approach: 1. Foundation (1-3 months), 2. Case Studies (3-6 months), 3. Practice (6-12 months), 4. Deepening/Specialization (12+ months).
    - **Why it matters:** Provides a structured, actionable roadmap for engineers aiming to improve system design skills.
