# How I Actually Use Opencode As A Senior Engineer

This source provides a practical, senior-level perspective on using [[OpenCode]] as a coding assistant. The author rejects the hype that AI will replace developers, arguing instead for a model where humans lead complex tasks and AI executes. It details specific workflows involving sub-agent specialization, security best practices like Just-in-Time (JIT) tokens, and the integration of OpenCode with tools like GitHub, Neovim, and SQLite.

## Key Insights

*   **AI as Assistant**: The author explicitly calls BS on the idea that AI will write 90% of code independently. AI is positioned as a high-efficiency assistant.
*   **Sub-Agent Specialization**: Using specialized sub-agents (e.g., for planning, building, reviewing) reduces hallucinations compared to monolithic agents.
*   **Security Priority**: Static API keys are described as a "massive security hole." The use of JIT tokens is advocated as a necessary security baseline.
*   **Tool Maturity**: OpenCode has evolved from a terminal-only tool to a multi-platform ecosystem with GUI, Web, and iPad support.
*   **Customization**: The best workflow aligns with the developer's habits rather than adopting rigid, pre-configured complex systems.
