# Learn in Public: Work as Learning

This source features insights from **Ryo Lu**, a designer and engineer with experience at **Cursor**, **Notion**, and **Stripe**. It argues that the traditional linear path of learning (theory → practice → job) is obsolete in the AI era. Instead, the nature of software design and engineering is undergoing a fundamental shift from static interface design to dynamic system manipulation. The central thesis is **"Work as Learning"**: simulating professional work immediately using AI tools to create verifiable artifacts, making verifiable work output the primary asset that supersedes traditional credentials.

## Core Arguments

### Software Design is Conceptual, Not Visual
Software is not merely pixels on a screen but a multi-layered structure of concepts and relationships (infrastructure → data → rendering). Excellent products can be decomposed into their core conceptual structures rather than user flows or visual decoration:
- **TikTok** is fundamentally a video list.
- **Notion** is built on blocks and databases.
- **Stripe** and **Notion** are defined by their underlying concepts and relationships, not just visual polish.

The evolution of UI from skeuomorphic to flat design is a process of exposing these true concepts rather than simulating reality. This aligns with the principle of **[[Essentialism in Design]]**, where stripping away non-essential elements reveals the underlying system and function, similar to industrial design artifacts like the **Eames Chair**.

### AI-Mediated Prototyping and the "Builder" Role
AI-powered tools like **Cursor** enable a **"build first, understand later"** paradigm. By lowering technical barriers (bypassing initial friction with Git, npm, and terminal syntax), designers and product managers can focus on system logic and collaborate iteratively with AI agents. This shifts the professional identity from specialized roles (Designer, PM, Engineer) to a unified **[[The Builder Role]]**, capable of delivering working systems.

- **Figma vs. Code Prototypes:** Static design tools like **Figma** are becoming obsolete for high-fidelity validation because they lack real data, logic execution, and state management. In contrast, code-based prototyping provides immediate feedback on edge cases, system behavior, and enables real AI integration.
- **Strategic Requirements:** While AI lowers technical friction, it raises the bar for **aesthetic judgment** and **system thinking** to avoid "AI slop" (generic, messy AI output). Designers must possess strong graphic design fundamentals (typography, hierarchy) to effectively curate AI-generated code.
- **Collaboration Model:** Effective AI use relies on **AI-Mediated Iterative Collaboration** (plan → build → refine) rather than one-shot generation.

### Verifiable Capability and "Learn in Public"
In software engineering, one can "become" an engineer before being hired by simulating professional work conditions at home. Unlike fields like medicine or architecture, software production is dematerialized, allowing for remote simulation of professional work. Consequently, hiring is shifting from credential-based (degrees) to evidence-based (GitHub repos, live demos, runnable portfolios).

The practice of **[[Learn in Public]]** involves acquiring skills by actively performing professional tasks and sharing the output publicly. This shifts identity from "student" to "practitioner," establishing that competence is developed through public creation and iteration rather than passive consumption.

## Methodology & Practice

### High-Information Density Learning Diary
The source proposes a framework for compressing learning into actionable insights:
1. **Insight:** Identify the core cognitive shift (e.g., "Software is concept manipulation").
2. **Old Model vs. New Model:** Contrast previous assumptions with new realities (e.g., "Learn then work" vs. "Work is learning").
3. **First Principles:** Define the underlying truth (e.g., "Career competitiveness = Real Experience × Demonstrability").
4. **Actionable Conversion:** Translate insights into specific behaviors (e.g., "Build one runnable demo per week").
5. **Self-Questioning:** Reflect on the verifiability of current efforts.

### Practical Recommendations
1. **Stop doing static design only:** Shift from Figma-only workflows to code-based prototyping.
2. **Build weekly:** Create at least one running demo per week using **Cursor** and AI agents.
3. **Master System Thinking:** Understand the core concepts of products (e.g., CRUD, lists, objects) rather than just UI patterns.
4. **Embrace Version Control:** Learn Git branching and checkpointing to manage iterative development safely.
5. **Curate AI Output:** Apply strong graphic design principles to refine AI-generated interfaces, avoiding "AI slop."

## Key Concepts
* **[[Essentialism in Design]]:** Long-lasting design strips away non-essential elements to reveal underlying structure and function.
* **Conceptual System vs. Interface:** Software is a multi-layered structure of concepts and relationships, not just pixels.
* **[[Learn in Public]] / Learning by Building:** Competence is developed through public creation and iteration rather than passive consumption.
* **AI-Mediated Iterative Collaboration:** Using AI agents for continuous, context-aware collaboration rather than one-shot generation.
