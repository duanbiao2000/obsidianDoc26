# Make a Dense Technical Spec Feel Alive and Embodied, Not Just Parseable

This source is a poetic, metaphorical description of the architecture of an AI coding agent — likely [[Claude Code]]. Its core argument is that a dense technical specification should *feel* alive and embodied, not merely be parseable by machines. The author demonstrates this claim through a series of human, relatable metaphors for each architectural component.

## Key Metaphors

| Component | Metaphor |
|-----------|----------|
| Agent loop | "the heartbeat" — runs beneath everything, perceiving, deciding, acting |
| Tools | "the hands" — `bash`, `read`, `write`, browser; unremarkable in themselves, but essential |
| On-demand skill loading | "a jazz musician who doesn't play every note he knows" |
| Context compression | "describing a book you read three years ago" — the art of forgetting carefully |
| Subagents | "the selves you send out" — you stay at the desk, they go and return |
| Task system | "a dependency graph has an understanding of time that a list does not" |
| Async mailboxes | "notes under a door" — agents leave messages, nobody holds a meeting |
| Worktree isolation | "each parallel process has its own room" |
| Permission governance | "a well-trained dog who knows exactly where the yard ends" |

## Contribution to the Wiki

This source adds a **poetic register** to the existing technical documentation. It does not introduce new technical facts but reframes known concepts in a way that is more memorable and more useful for language learning. The vocabulary list at the end provides C1/C2 words (parseable, embodied, posture, governance) with IELTS-style analysis, making it a dual-purpose resource: both a model for writing about architecture and a language learning tool.
