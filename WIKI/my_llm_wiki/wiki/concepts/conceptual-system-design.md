# Conceptual System Design

**Conceptual System Design** is a design theory that views software as a multi-layered structure of concepts and relationships (infrastructure → data → rendering), rather than just a collection of user interface pixels.

## Key Tenets

*   **Software as Concepts:** The essence of software lies in its conceptual model (e.g., **Notion** as blocks and databases, **TikTok** as a video list). UI is merely one expression of this underlying system.
*   **Design from Structure:** Effective design starts from the conceptual structure and data relationships, not from user flows or visual decoration.
*   **Essentialism:** Simplifying design to its core function and structure removes non-essential visual noise while maintaining character, similar to industrial design principles seen in the **Eames Chair**.

## Implications for Builders

For those adopting **[[The Builder Role]]**, understanding the conceptual system is crucial. It requires moving beyond static design tools like **Figma** to engage with executable code, where real data, logic, and state management reveal edge cases and system behaviors that static mockups cannot. This approach aligns with **[[System Mindset-Documentation Engineering]]**, emphasizing that deep understanding of data structures is key to both good design and robust documentation.
