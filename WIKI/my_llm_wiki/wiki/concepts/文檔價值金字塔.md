# 文檔價值金字塔 (Document-Value-Pyramid)

**文檔價值金字塔**是一個將技術文檔依據其對用戶和組織的價值與影響力，從基礎到戰略層級劃分的模型。它提供了一個結構化的框架來理解和優先級排序不同類型的文檔，旨在最大化文檔對組織效率、知識傳承和戰略決策的貢獻。此模型也被稱為[[L7級技術文檔優先級模型]]或 L7 文檔模型。

## 金字塔層級

文檔價值金字塔包含五個主要層級，從底層到頂層，其對組織的戰略價值和影響力逐漸提升：

1.  **Getting Started (基礎層)**：
    *   **核心問題**：如何快速上手？
    *   **價值邏輯**：具有最高的[[onboarding-roi|投資回報率 (ROI)]]。每個新用戶都會經歷入門過程，降低首次失敗成本能減少組織最大的隱性損耗。
    *   **內容**：快速入門指南、最小可運行範例、環境配置、5 分鐘演示。

2.  **Task Execution Docs (高頻操作層)**：
    *   **核心問題**：我現在要完成 X，該怎麼做？
    *   **價值邏輯**：解決高頻重複操作，用戶以搜索導向，可直接複製貼上執行。
    *   **內容**：API 調用指南、服務部署步驟、插件編寫說明、tokens 計算方法。

3.  **Common Failure Guides (L6 分水嶺)**：
    *   **核心問題**：為什麼會失敗？
    *   **價值邏輯**：透過[[失敗優先邏輯]]減少失敗來最大化效率提升。用戶失敗次數通常多於成功次數，解決常見失敗能顯著提升團隊效率。
    *   **內容**：常見錯誤原因、調試清單、反模式、性能陷阱/限流處理。

4.  **System Mental Models (L6 層)**：
    *   **核心問題**：系統是如何思考的？
    *   **價值邏輯**：幫助用戶建立正確的[[系統心智模型-文檔工程|系統心智模型]]，減少錯誤抽象，使其能自主推理，不再過度依賴文檔。
    *   **內容**：請求生命週期圖、數據流模型、緩存機制、Agent 執行流程。

5.  **Strategic Decision Docs (L7 層)**：
    *   **核心問題**：為什麼系統被設計成這樣？
    *   **價值邏輯**：作為「組織記憶層」，防止組織重複討論，讓新負責人快速繼承上下文，關注組織規模化和未來系統。
    *   **內容**：[[architecture-decision-records-adr|架構決策記錄 (ADR)]]、權衡分析、被拒絕的替代方案、擴展理由。

## L6 與 L7 的關注點差異

*   **L6 (團隊效率)**：關注減少重複問題，時間尺度是當前系統，輸出形式是操作手冊 (Playbook)。
*   **L7 (組織規模化)**：關注改變思考方式，時間尺度是未來系統，輸出形式是原則 (Principles)。

## 應用意義

文檔價值金字塔模型強調了文檔在[[技術管理]]、[[組織效能]]和[[知識管理-pkm]]中的戰略作用。透過理解不同層級文檔的獨特價值，組織可以更明智地分配資源，確保關鍵知識的有效傳播和保留，從而支持持續的創新和成長。
