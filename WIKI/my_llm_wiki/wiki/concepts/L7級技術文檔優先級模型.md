# L7級技術文檔優先級模型

**L7級技術文檔優先級模型**，又稱[[文檔價值金字塔]]或 L7 文檔模型，是一個將技術文檔依據其對用戶和組織的價值與影響力，從基礎到戰略層級劃分的框架。此模型旨在幫助技術團隊和組織有效地評估、創建和維護不同類型的文檔，以最大化其投資回報率和長期效益。

## 模型層級與價值

該模型將文檔分為五個層級，每個層級解決不同的核心問題，提供獨特的價值：

1.  **Getting Started (基礎層)**
    *   **核心問題**：如何快速上手？
    *   **價值**：最高的[[onboarding-roi|投資回報率 (ROI)]]。透過降低新用戶或新成員的首次失敗成本，減少組織最大的隱性損耗。
    *   **內容範例**：快速入門指南、最小可運行範例、環境配置、5 分鐘演示。

2.  **Task Execution Docs (高頻操作層)**
    *   **核心問題**：我現在要完成 X，該怎麼做？
    *   **價值**：提升高頻重複操作的效率。用戶以搜索導向，可直接複製貼上執行，無需理論鋪墊。
    *   **內容範例**：API 調用指南、服務部署步驟、插件編寫說明、tokens 計算方法。

3.  **Common Failure Guides (L6 分水嶺)**
    *   **核心問題**：為什麼會失敗？
    *   **價值**：透過[[失敗優先邏輯]]顯著提升效率。用戶失敗次數通常多於成功次數，解決常見失敗能為高成熟團隊帶來高達 30% 的效率提升。
    *   **內容範例**：常見錯誤原因、調試清單、反模式、性能陷阱/限流處理。

4.  **System Mental Models (L6 層)**
    *   **核心問題**：系統是如何思考的？
    *   **價值**：幫助用戶建立正確的[[系統心智模型-文檔工程|系統心智模型]]，減少錯誤抽象，使其能自主推理，不再過度依賴文檔。
    *   **內容範例**：請求生命週期圖、數據流模型、緩存機制、Agent 執行流程。

5.  **Strategic Decision Docs (L7 層)**
    *   **核心問題**：為什麼系統被設計成這樣？
    *   **價值**：作為「組織記憶層」，防止組織重複討論，讓新負責人快速繼承上下文，關注組織規模化和未來系統。
    *   **內容範例**：[[architecture-decision-records-adr|架構決策記錄 (ADR)]]、權衡分析、被拒絕的替代方案、擴展理由。

## L6 與 L7 的關注點差異

*   **L6**：主要關注**團隊效率**，目標是減少重複問題，時間尺度是**當前系統**，輸出形式是操作手冊 (Playbook)。
*   **L7**：主要關注**組織規模化**，目標是改變思考方式，時間尺度是**未來系統**，輸出形式是原則 (Principles)。

## 應用與意義

L7級技術文檔優先級模型強調了文檔在[[技術管理]]、[[組織效能]]和[[知識管理-pkm]]中的戰略作用。它鼓勵組織將文檔視為一種投資，並根據其對業務的實際影響來分配資源，從而確保文檔能夠有效地支持團隊的日常運作和組織的長期發展。
