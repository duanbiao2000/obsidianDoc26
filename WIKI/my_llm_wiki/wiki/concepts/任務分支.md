# 任務分支

[[任務分支]]是指在 Git 版本控制系統中，為特定任務或功能開發而創建的獨立分支。在結合 [[Git Worktree]] 和 [[工作樹-task-isolation]] 機制時，每個隔離的工作樹通常會對應一個獨立的任務分支。

## 核心概念

*   **獨立開發線**：每個任務分支都提供了一個獨立的開發線，允許開發者或 AI 代理在不影響主分支或其他任務分支的情況下進行程式碼修改。
*   **任務綁定**：一個任務分支通常與一個特定的任務 ID 或功能需求綁定，其所有提交都圍繞該任務進行。
*   **隔離性**：在 [[工作樹-task-isolation]] 的語境下，任務分支與一個獨立的工作目錄（由 [[Git Worktree]] 管理）相關聯，確保任務的執行環境是完全隔離的。

## 重要性

*   **實現任務隔離**：透過將每個任務的修改限制在一個專屬分支上，可以有效防止不同任務之間的程式碼衝突和環境污染。
*   **簡化版本控制**：每個任務的進度都清晰地體現在其對應的分支上，便於追蹤、管理和審查。
*   **促進並行開發**：多個開發者或 AI 代理可以同時在不同的任務分支上工作，而無需等待彼此完成。
*   **便於回滾和清理**：如果一個任務失敗或不再需要，可以輕鬆地刪除其任務分支和對應的工作樹，而不會影響主程式碼庫。

## 命名約定

為了清晰地識別和管理，任務分支通常會遵循特定的命名約定，例如：

*   `feature/task-id-feature-name`
*   `bugfix/task-id-bug-description`
*   `task/agent-name-task-id` (在 AI 代理場景中)

## 與 [[Git Worktree]] 的關係

[[Git Worktree]] 是實現任務分支隔離的關鍵工具。它允許在同一個 Git 倉庫中，為每個任務分支創建一個獨立的工作目錄。這樣，當一個 AI 代理在處理 `task/agent-1-feature` 分支時，它會在 `/path/to/worktree/task-agent-1` 目錄中進行操作，而不會影響到主分支或其他任務分支的程式碼。

## 合併流程

當一個任務在其任務分支上完成後，該分支的修改需要合併回主分支。這個過程遵循[[git-worktree-合併流程]]中描述的標準 Git 合併步驟，包括處理潛在的程式碼衝突。

總之，[[任務分支]]是實現高效、安全和可追溯的並行開發和 AI 代理任務管理的基礎。
