**“Obsidian 知识图谱的定制渲染”**，不是简单把 Obsidian 默认的 Graph View 换一种颜色，而是把你的 Markdown 笔记、链接、标签、属性和时间信息抽取成一张“语义网络”，再按你真正关心的结构进行可视化。

对你而言，它可以把现有的 **Input → Internalize → Output** 学习体系、技术项目、YouTube 笔记、论文和原子卡片，渲染成可探索的知识地图，而不是一个随机漂浮、主要展示链接数量的“星空图”。Obsidian 原生 Graph View 只能基于笔记链接展示关系，但可用搜索筛选、颜色分组和 Local Graph 深度控制；Canvas 则适合手动组织卡片与连接。 [obsidian](https://obsidian.md/help/plugins/graph)

## 三种“图谱”别混淆

| 类型                  | 本质                             | 优点                   | 局限                                  |
| ------------------- | ------------------------------ | -------------------- | ----------------------------------- |
| Obsidian Graph View | 自动读取 `[[双链]]` 的网络图             | 零配置、快速发现孤立笔记与连接节点    | 关系没有语义；线条只表示“有链接”                   |
| Obsidian Canvas     | 手动排列笔记、图片、文本卡片和连线              | 适合思考、讲解、规划、做视觉地图     | Canvas 连线通常只是画布关系，不等于写回 Markdown 双链 |
| Dataview 页面         | 根据 frontmatter / 标签生成表格、列表、任务页 | 适合结构化筛选和 dashboard   | 不是空间图谱                              |
| 自定义图谱渲染器            | 根据你的 schema 生成专属交互地图           | 可表达关系类型、时间、学习阶段、任务状态 | 需要设计数据结构与编程                         |

Obsidian 的 Global Graph 显示整个 vault 的连接；Local Graph 只显示当前笔记及其邻近关系，并可控制显示深度。你还可以使用搜索条件过滤节点、隐藏附件/孤立笔记，以及按搜索条件给不同笔记群组上色。 [obsidian](https://obsidian.md/help/plugins/graph)

Canvas 是无限二维画布，可以摆放笔记、图片和其他文件，以有方向的连线连接它们，还可创建和命名分组；它非常适合“手动构图”。但应把它视为**视觉工作台**，而不是自动维护知识事实的数据库。 [obsidian](https://obsidian.md/help/plugins/canvas)

## 为什么默认图谱常常没用

Obsidian 默认 Graph View 的数据大致只有：

```text
笔记 A  ──链接──> 笔记 B
```

但它不知道：

```text
A 是定义，还是例子？
B 是前置知识，还是反驳观点？
这条链接是“学习顺序”、还是“引用来源”？
哪个笔记是输入材料，哪个已内化，哪个是输出项目？
哪个内容正在进行，哪个已废弃？
```

于是默认图谱常变成：

```text
连接多的笔记 = 大节点
连接少的笔记 = 小节点
大量交叉线 = 一团毛线
```

它的视觉冲击很强，但实际决策价值可能很低。

真正有用的图谱需要从：

```text
有链接吗？
```

升级到：

```text
这是什么类型的知识？
它与其他知识是什么关系？
它当前处于学习或项目流程的哪个阶段？
我下一步应该做什么？
```

## 你的图谱可以长什么样

你已有很适合图谱化的结构：

```text
Input
→ Vision / Observe / Audiobooks / YouTube / Papers

Internalize
→ Shadowing / 零摩擦冷静复读 / Anki / 阅读笔记 / 原子卡

Output
→ SHERO / Me and Mine / 视频 / 脚本 / 自动化项目 / 公开文章
```

把它转成知识图谱后，不只是“笔记互相连着”，而是可以显示**知识流动**：

```text
YouTube 视频
    ↓ 提炼
视频摘要
    ↓ 选择性吸收
原子概念卡
    ↓ 复习、跟读、实验
英语表达 / 技术能力
    ↓ 应用
视频脚本 / 软件项目 / 教程 / 自动化工具
```

例如你最近研究的主题可以形成：

```text
AI Agent 工作流
├─ Herdr
│  ├─ terminal multiplexer
│  ├─ persistent sessions
│  └─ agent state awareness
├─ FirstMate
│  ├─ multi-agent orchestration
│  └─ worktree isolation
├─ Muse Code
│  ├─ terminal coding agent
│  └─ parallel agents
├─ Claude Code
│  ├─ MCP
│  ├─ CLAUDE.md
│  └─ background agents
└─ Output
   └─ 你的 Agent 开发环境与使用规范
```

定制渲染后可以让不同关系具有不同含义：

| 关系              | 图中线条含义 | 示例                             |
| --------------- | ------ | ------------------------------ |
| `depends_on`    | 前置依赖   | `Home Manager → Nix Flakes`    |
| `implements`    | 具体实现   | `Herdr → terminal multiplexer` |
| `compares_with` | 对比关系   | `Zellij ↔ tmux`                |
| `extends`       | 扩展/增强  | `FirstMate → Claude Code`      |
| `learned_from`  | 来源关系   | `你的笔记 → YouTube 视频`            |
| `supports`      | 证据支持   | `论文 → 某项结论`                    |
| `contradicts`   | 反驳/冲突  | `观点 A ↔ 观点 B`                  |
| `applies_to`    | 实际应用   | `wgpu → 音频可视化项目`               |
| `produces`      | 从输入到输出 | `英语 Shadowing → 口语表达项目`        |

这比“所有线都是灰色”的默认 Graph View 有意义得多。

## 先建立数据结构

图谱质量主要不取决于渲染器，而取决于你的笔记有没有可读的元数据。不要一开始就写 wgpu；先让笔记结构稳定。

推荐在重要笔记顶部增加 frontmatter：

```yaml
---
type: concept
stage: internalize
status: evergreen

topics:
  - ai-agents
  - developer-tools

source_type: youtube
source_url: https://www.youtube.com/watch?v=VIDEO_ID

created: 2026-09-14
updated: 2026-09-14

prerequisites:
  - "[[Terminal multiplexer]]"
  - "[[Git worktree]]"

related:
  - "[[Herdr]]"
  - "[[FirstMate]]"

applies_to:
  - "[[Agent workflow setup]]"
---
```

你不必每篇笔记都写这么多字段。可以先只固定以下五个：

```yaml
type:
stage:
topics:
status:
related:
```

例如：

```yaml
---
type: video-note
stage: input
topics: [english, pronunciation]
status: processed
---
```

或：

```yaml
---
type: project
stage: output
topics: [ai-agents, automation]
status: active
---
```

这样你的知识图谱就不再只依赖 `[[链接]]`，而有了可筛选、可着色、可统计和可渲染的语义。

## 用 Obsidian 原生功能先做

在开发自定义渲染之前，建议先从原生 Graph View 验证你的分类是否合理。

### 建立颜色分组

打开：

```text
Graph View
→ Graph Settings
→ Groups
→ New Group
```

添加类似搜索规则：

```text
path:"Input"
```

或：

```text
stage:input
```

如果使用标签：

```text
tag:#input
```

为它设置蓝色。

然后：

```text
path:"Internalize"
```

设置紫色或青色。

最后：

```text
path:"Output"
```

设置橙色、金色或绿色。

Obsidian Graph View 支持通过 Search files 过滤显示节点，也支持按搜索条件创建 Groups 并分配颜色。 [obsidian](https://obsidian.md/help/plugins/graph)

你的图谱视觉上可变成：

```text
蓝色节点：输入材料
紫色节点：正在内化的概念、词块、读书卡
金色节点：项目、文章、视频和其他输出
```

这已经比默认图谱有用很多。

### 使用 Local Graph

打开当前笔记的局部图：

```text
Ctrl + P
→ Open local graph
```

然后把深度先设为：

```text
Depth: 1 或 2
```

例如你打开 `[[Home Manager]]` 时，Local Graph 可能展示：

```text
Nix
├─ Flake
├─ Home Manager
│  ├─ home.nix
│  ├─ common.nix
│  ├─ Neovim configuration
│  └─ Ubuntu / WSL setup
└─ NixOS
```

局部图更适合回答：

```text
这个概念关联了什么？
我应该先学哪几个前置知识？
这一条笔记是否真的连接进知识网络？
```

而不是试图一次看懂整个 vault。Local Graph 可独立设置深度，每增加一层就显示上一层节点所连接的更多笔记。 [obsidian](https://obsidian.md/help/plugins/graph)

## Canvas 更适合“讲故事”

你的知识库里有两类可视化需求，应分别处理。

```text
自动发现结构
→ Graph View / 自定义渲染器

人为组织叙事
→ Canvas
```

例如做一个关于 Nix 的教学 Canvas：

```text
[Nix]
  ↓
[Flake]
  ↓
[Home Manager]
  ↓
[Ubuntu / WSL User Environment]
  ↓
[Neovim / Git / Zsh / Yazi]
```

你可以在 Canvas 中：

- 放置 `[[Nix]]`、`[[Flake]]`、`[[Home Manager]]` 等真实笔记卡；
- 放置终端命令、截图、流程说明；
- 用箭头表示学习顺序；
- 为 Input、Internalize、Output 建立视觉分组；
- 双击连接线添加关系标签，例如 `depends on`、`produces`、`practice`。

Canvas 支持把笔记、图片和其他文件放进二维空间，使用有方向的线连接卡片，并创建可命名的 group；连接线也可添加标签。 [obsidian](https://obsidian.md/help/plugins/canvas)

但一个关键原则是：

> **Canvas 用于说明和思考；Markdown 双链和 frontmatter 用于保存真实的、可查询的知识关系。**

不要只在 Canvas 中拉线，却不在笔记中保留任何链接或 metadata；否则未来 Graph、Dataview 和自定义工具都很难找到这种关系。

## Dataview 是图谱的数据层

Dataview 不直接画复杂图，但它是你做定制图谱前最有价值的“数据检查器”。

例如，建立一篇：

```text
Dashboard - AI Agents.md
```

写入：

```dataview
TABLE
  type AS "类型",
  stage AS "阶段",
  status AS "状态",
  file.mtime AS "最后更新"
FROM #ai-agents
SORT file.mtime DESC
```

这会把带有 `#ai-agents` 标签的笔记变成一个项目表。

再例如，找出所有还没从 Input 进入 Internalize 的视频笔记：

```dataview
TABLE
  source_url AS "视频",
  file.mtime AS "记录时间"
FROM "Input"
WHERE type = "video-note"
  AND status != "processed"
SORT file.mtime DESC
```

Dataview 会索引 vault 中的 metadata，并支持 DQL、Inline Expressions、DataviewJS 等四种查询方式；DataviewJS 还能直接使用 JavaScript 获取索引数据并自行渲染结果。 [community.obsidian](https://community.obsidian.md/plugins/dataview)

这意味着你在写 wgpu 图谱前，可以先问：

```text
我的 type 是否一致？
stage 有没有混乱？
哪些笔记没有 topic？
哪些输出项目没有对应输入？
哪些高价值笔记没有任何连接？
```

数据干净后再可视化，价值才高。

## 什么叫 wgpu 定制渲染

如果进一步使用 Rust + wgpu，你可以做一个独立桌面程序或 WebAssembly 可视化器：

```text
Obsidian Vault
   ↓
解析 Markdown + YAML frontmatter + [[links]]
   ↓
生成知识图数据
   ↓
Node / Edge / Metadata
   ↓
布局算法
   ↓
wgpu 渲染成可缩放、可筛选、可交互的图谱
```

技术上可以分成：

```text
输入层
├─ Markdown 文件
├─ YAML frontmatter
├─ Obsidian wiki links
├─ Dataview metadata
└─ YouTube / Paper / Git 项目元数据

图模型层
├─ Node：笔记、视频、论文、项目、概念
├─ Edge：引用、依赖、反驳、应用、来源、复习
├─ Attribute：type、stage、status、topic、created
└─ Filter：按时间、主题、知识阶段、项目筛选

布局层
├─ Force-directed graph：自动按连接关系聚集
├─ Hierarchical layout：按学习路径上下排列
├─ Timeline layout：按日期排列
├─ Radial layout：围绕一个中心概念展开
└─ Sankey-like flow：显示 Input → Internalize → Output 流动

渲染层
├─ wgpu：画节点、线条、标签、图片缩略图
├─ WGSL：处理颜色、光晕、选择效果、动画
├─ GPU picking：点击识别节点
└─ Zoom / Pan：缩放和平移
```

wgpu 的价值在于：当你的 vault 有几千甚至上万条笔记、节点带缩略图、需要大量动态连线、颜色渐变、动画筛选或实时布局时，GPU 渲染会比简单 DOM 或 SVG 图更流畅。wgpu 是跨平台的 Rust GPU API，原生可对接 Vulkan、Metal、D3D12 和 OpenGL，并可在 WebAssembly 环境中使用 WebGPU/WebGL2。 [docs](https://docs.rs/wgpu/latest/wgpu/)

## 值得做的六种视图

### 1. 学习流图

这是最适合你的第一种自定义图。

```text
Input
├─ YouTube
├─ Audiobooks
├─ Articles
└─ Papers
      ↓
Internalize
├─ Summary
├─ Concept card
├─ Shadowing
├─ Anki
└─ Experiments
      ↓
Output
├─ Tutorial
├─ Video script
├─ Software project
├─ Automation script
└─ Public article
```

每个节点大小可以表示：

```text
引用次数
复习次数
最近活跃度
完成度
```

颜色可以表示：

```text
蓝色：Input
紫色：Internalize
金色：Output
灰色：Archived / 未处理
红色：Blocked / 缺少前置知识
```

这张图回答的是：

> 我的输入是否真的被转化成了内化和输出？\
> 哪些主题收集了很多资料，但一直没有形成行动？\
> 哪些输出项目缺少可靠来源或概念基础？

### 2. 概念前置依赖图

例如英语、Nix、Rust 或图形编程：

```text
Rust
├─ Ownership
├─ Borrowing
├─ Cargo
├─ Traits
└─ Async
      ↓
wgpu
├─ Surface
├─ Device
├─ Buffer
├─ WGSL
└─ Render Pipeline
      ↓
Audio Visualizer Project
```

它适合回答：

> 我卡在某个概念时，真正缺的是哪一层前置知识？

这种图比普通脑图更好的一点是：每一个节点都能直接打开对应 Obsidian 笔记、视频时间戳、代码仓库或实验记录。

### 3. 论证图

适用于哲学、社会理论、书籍阅读和文章写作：

```text
中心主张
├─ 支持证据
│  ├─ 论文
│  ├─ 统计资料
│  └─ 例子
├─ 反驳意见
│  ├─ 理论反例
│  └─ 经验反例
└─ 你的结论
```

边不再只是“有链接”，而是：

```text
supports
contradicts
qualifies
defines
illustrates
```

这很适合防止笔记变成“摘抄堆积”，而让你清楚知道：某个观点到底有何证据、反对意见是什么、自己的立场在哪里。

### 4. 时间演化图

对于 AI Agent、Rust 图形 API、Linux 配置或一门学科的学习历程：

```text
2026-01
→ 初次接触 tmux / Zellij

2026-03
→ 开始使用 Claude Code

2026-06
→ 多 Agent 编排与 FirstMate

2026-09
→ Herdr / Muse Code / Nix Home Manager
```

节点横轴是时间，纵轴是主题；链接表示概念如何演化。它适合做“研究路线回顾”和视频选题规划。

### 5. 项目—知识双向图

```text
Project: Voice Input Workflow
├─ Handy
├─ PipeWire
├─ GNOME Wayland
├─ Whisper / Parakeet
├─ Keyboard Remapping
└─ Input Remapper
```

每个项目节点连向它依赖的概念、工具、教程、脚本和故障排查记录。

这能帮助你回答：

> 这个项目如果半年后出问题，我需要先回顾哪些笔记？\
> 我学过哪些内容，其实已经足够支撑一个可输出项目？

### 6. 视频知识地图

你会保存 YouTube 视频和精确时间戳，可以把每个视频作为 source 节点：

```text
YouTube Video
├─ Timestamp 02:59 → 概念 A
├─ Timestamp 08:42 → 实例 B
└─ Timestamp 14:10 → 工作流 C
```

再把概念连到你的 Anki、项目、英文词块和其他资料。

这比仅保存一个 YouTube 链接更有用，因为视频不再只是“待看资源”，而是可被检索、引用和复习的知识来源。

## 实现路线建议

不要直接从 wgpu 开始。最可靠的路线是：

### 阶段一：整理关系语义

先在 Markdown 中建立最小 schema：

```yaml
type:
stage:
topics:
status:
related:
prerequisites:
source_url:
```

目标不是完美，而是让 50–100 篇重要笔记拥有一致属性。

### 阶段二：用原生 Graph + Dataview 验证

使用：

```text
Graph View
Local Graph
Canvas
Dataview
```

检查哪些字段真正有用，哪些只是增加填写负担。

### 阶段三：先写一个浏览器原型

对于图谱可视化，第一版不必 Rust/wgpu。可以用：

```text
TypeScript
+ Obsidian plugin API 或独立网页
+ D3.js / Cytoscape.js / Sigma.js
+ JSON 导出的 vault graph
```

原因是第一版最难的通常不是 GPU 渲染，而是：

```text
如何定义节点？
如何定义边？
如何过滤噪声？
怎样布局才对你有意义？
点击后如何跳到笔记？
```

### 阶段四：需要性能或视觉表达时再上 wgpu

当你确认自己需要：

```text
数千到数万节点
图片缩略图
高帧率缩放和平移
动态 GPU force layout
带动画的知识流
可录屏的高质量视觉效果
```

再使用：

```text
Rust
+ pulldown-cmark
+ YAML frontmatter parser
+ petgraph
+ winit
+ wgpu
+ egui 或自定义 WGSL UI
```

此时 wgpu 不只是“为了酷”，而是确实承担了高性能渲染和视觉叙事的任务。

## 最重要的原则

```text
Markdown 是事实来源
frontmatter 是结构化语义
[[双链]] 是基础关系
Canvas 是手动叙事
Dataview 是查询层
自定义图谱是观察和决策层
```

不要反过来，让漂亮的图谱成为唯一真相。最好的知识图谱不是一个视觉特效，而是让你更快发现：

```text
哪些输入没有被吸收？
哪些概念缺少前置知识？
哪些项目缺少资料、实验或论证？
哪些主题已经足够成熟，应该进入输出？
哪些笔记是孤岛，应该删除、合并或建立连接？
```

对你而言，最有价值的第一个成品不是“全库星空图”，而是一个 **Input → Internalize → Output 知识流图**：它能直接显示你收集的视频、论文和工具资料，最终是否真的转化成英语能力、自动化脚本、技术笔记、视频和实际项目。
