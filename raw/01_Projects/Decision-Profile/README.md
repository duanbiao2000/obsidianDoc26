# Decision-Profile · 使用手册

> 决策前读画像 → 决策后回写卡片 → 定期提炼画像。**这是一套持续升级的个人决策系统，不是一次性的记录工具。**

## 1. 这个项目解决什么问题

没有系统时，重大决策通常是这样结束的：凭感觉做决定 → 事后发现同一个坑反复踩 → 自己总结不出规律。本项目把「决策」变成一条可回放的闭环：

1. **决策前**：调用你的决策画像（已知盲点）+ 匹配 2-3 个精选范式（视角），带着防偏装置做判断；
2. **决策后**：结果回写决策卡，成为事实数据；
3. **定期**：从卡片归纳 → 画像升版 → 盲点确认/反驳 → 范式使用效果更新。

它直接落地 [[2026-07-11-自我服务]] 的「AI 协同自我服务 + 红蓝对抗 loop」，并把「AI 执行、人当主审」用在你自己的决策上。

## 2. 目录结构

| 路径 | 作用 |
| :--- | :--- |
| `MOC-Decision-Profile.md` | 项目入口：导航 + 决策卡列表 |
| `Profile.md` | ★ 决策画像：唯一会「升级」的核心总表 |
| `Cards/` | 决策卡：每个重大决策一页（事实层） |
| `Paradigms/` | 范式库：决策前的视角库 + 匹配索引 |
| `Paradigms/Future-Expansion.md` | 更全的外部高手范式库（后续升级候选） |
| `Templates/Decision-Card.md` | 新建决策卡时复制的模板 |

## 3. 四条铁律（违反任意一条，系统就会退化）

1. **Cards 是事实，Profile 是结论。** Profile 只能从 Cards 归纳，不凭空写；没有卡片支撑的盲点不算数。
2. **范式是视角，不是答案。** 每次只选 2-3 个，决策权始终在你；范式解决「看什么」，不解决「选什么」。
3. **只记录值得 loop 的决策。** stakes = high/medium（影响面大或不可逆）才建卡；琐碎决定不进系统，避免记录本身变成新的低价值摩擦。
4. **定期提炼 > 频繁记录。** 每满 5 张卡或每季度提炼一次画像，时长 45-60 分钟。

## 4. 标准流程（一次完整闭环）

### 阶段 A：决策前（30-60 分钟）

1. 打开 `MOC-Decision-Profile.md`，先读 `Profile.md` 的「决策前调用清单」和「已知盲点」。
2. 复制 `Templates/Decision-Card.md` → `Cards/2026-MM-DD-决策-<主题>.md`。
3. 填写卡片第 1 节（决策概述）和第 2 节（画像快照）。
4. 打开 `Paradigms/00-Paradigm-Index.md`，按「决策类别 × 风险等级 × 盲点」选 2-3 个范式，把核心问题写进第 2 节。
5. 跑红蓝对抗 loop（规格见 [[2026-07-11-自我服务]] 第五节）：
   - **GOAL**：穷尽最致命盲点，输出带对冲方案的清单；
   - **EACH ITERATION**：红方批判（只许新盲点）→ 蓝方对冲 → 输出 vN；
   - **VERIFY**：去重校验 + 证据校验 + 硬校验（最致命 3 条必须用真实信息核对）；
   - **STOP WHEN**：连续两轮无新盲点，且最致命 3 条已通过真实核对。
6. 填写第 3、4 节：盲点与对冲、最终判断、理由、信心分、触发条件。

### 阶段 B：决策落地后（10 分钟）

7. 回填第 5 节：实际结果、与原判断的偏差、一句话教训。
8. 写第 6 节：1-2 条画像更新建议 + 本次范式使用效果（有用/没用/为什么）。

### 阶段 C：定期提炼（每 5 张卡或每季度，45-60 分钟）

9. 汇总所有 Cards，按「画像升级规则」更新 `Profile.md`，升版 vN → vN+1 并写 changelog。
10. 更新 `Paradigms/00-Paradigm-Index.md` 的使用记录：哪些范式被验证有用，哪些应降权。

## 5. 决策卡填写指南

- **第 1 节**：问题写「要决定什么」而非「想怎么决定」；选项至少 2 个，不要只写你倾向的那个。
- **第 2 节**：画像快照必须在跑 loop **之前**写——它防的是「先有答案再找理由」。
- **第 3 节**：每条盲点必须能回答「如果它成立，最坏会怎样」；硬校验记录真实信息来源（人/数据/文档）。
- **第 4 节**：信心分（0-5）写下当下的数值，事后不准改——它是校准数据。「如果…那么…」触发条件用于落地后的止损/调整。
- **第 5 节**：结果至少等决策真正落地（可观察）再写，不要当天凭感觉写。
- **第 6 节**：只写「可进入 Profile」的条目；范式效果一句话即可。

## 6. 画像升级规则

- 候选 → 确认：某盲点或优势在 ≥2 张卡复现 → 升级为确认条目；
- 反驳 → 降级：某条被新卡片证据反驳 → 附反驳卡链接并降级为「待复核」；
- 每条画像条目必须有证据卡链接（可反向追溯）；
- 每次升版在 changelog 写 3 行以内：新增 / 修正 / 删除。

## 7. 范式库使用规则

- 匹配入口：`Paradigms/00-Paradigm-Index.md` 的速查表；
- 每次决策只取 2-3 个；同视角避免重复（如「逆向思维」与「pre-mortem」都指向反方向思考，取一个即可）；
- 新范式加入流程：先在 2 张不同类别的决策卡试用，2 次都有用才正式进索引；否则留在 `Future-Expansion.md`。

## 8. Agent skill 自动化（可选）

- skill 名称：`decision-loop`，位置：`.agents/skills/decision-loop/`；
- 作用：读到「帮我做个决策 / 跑红蓝对抗 / 推荐范式」时自动执行阶段 A；读到「决策结果 / 复盘」时执行阶段 B；读到「提炼画像」时执行阶段 C；
- 人工流程与 skill 流程共用同一套文件，不双轨。

## 9. 未来升级路径

- 更全的外部高手范式库（候选清单见 `Paradigms/Future-Expansion.md`）；
- 画像与 [[知识管理系统]] 的领域地图联动；
- 季度决策审计：决策数、盲点命中率、信心校准度（信心分 vs 实际结果）。
