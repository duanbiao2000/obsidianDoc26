# 认知工作流复盘写作规范

## 适用场景
- 用户要求回顾自身在使用特定认知工具（如 Obsidian, Notion, Roam）过程中犯过的错误、提炼的原则。
- 用户要求总结自己在英语口语学习、知识管理、工作流自动化方面的心得，且强调真实经验而非理论堆砌。
- 用户希望输出内容可直接作为个人知识库的原子笔记单元，便于未来检索和链接。

## 核心约束

### 1. 内容真实性
- 所有论点必须基于**个人实证数据**（如具体时间、频率、对比结果），禁止泛泛而谈。
- 若引用外部理论（如波兰尼的隐性知识），必须结合自身经历重新阐释，不得直接搬运。

### 2. 领域边界
仅限以下三个交叉领域，超出范围的内容需剔除：
- **认知进化**：思维模型、决策偏差、心智习惯、反馈回路。
- **英语口语高效流畅表达**：习得策略、句法压缩、情境记忆、微习惯训练。
- **工作流封装与迭代**：工具链构建（如 Obsidian）、自动化、减负冲刺、状态保持。

### 3. 风格基准（“哈佛式”标准）
- **简明清晰**：每句话逻辑独立可验证，不使用模糊修辞或情感渲染。
- **细节驱动**：每个论点至少附带一项可核查的细节（如“启动时间从 0.8s 增至 4.2s”）。
- **理性睿智**：论述结构遵循“问题 → 分析 → 解决方案 → 验证结果”闭环。
- **无废话**：每段首句为论点，后续为证据。避免“我认为”“我觉得”等主观冗余。

### 4. 受众定位
- 目标读者为追求**隐性知识内化**的高阶学习者，不关心浅层技巧。
- **禁止**提及地域、职业身份、年龄、性别等人口统计特征（如“上海”“大学生”）。

## 输出结构规范（原子笔记式）

### 整体层级
- 全文**仅有一个一级标题（H1）**，即文章总标题（如 `# 认知工作流外化与封装复盘`）。
- 全部内容块均使用**二级标题（H2）**，**不得使用三级或更低级别标题**。

### 每个 H2 为一个独立知识单元
- 标题必须是**具独立语义的名词性短语**（如 `[[三行滤网协议]]`），便于未来引用。
- 标题中**禁止**出现序号（“1.”、“2.”）或分类标签（“母笔记”“机制”“修正”等）。
- 内容自包含：定义问题 → 解释机制 → 给出实证 → 提出对策（或关联其他 H2）。

### 集群与枢纽链接
- 属于同一主题的多个 H2 按逻辑顺序排列。
- **每组主题的第一个 H2** 为该集群的“枢纽节点”：其末尾必须以 `*参见：……*` 的形式列出该集群所有其他 H2 的标题（作为显式双向链接）。
- 其他 H2 仅在本体内通过 `[[标题]]` 自由引用，不再承担同级汇总任务。

## 写作执行步骤

当触发本技能时，按以下顺序生成内容：

1. **采集原始素材**：从用户的输入或个人经验记忆中提取真实失败案例、改进过程、量化结果。
2. **归纳主题簇**：将经验抽象为 5~7 个核心反模式或原则，每个主题簇包含若干相互关联的 H2。
3. **确定 H1 标题**：用一句概括全文结论（如“认知工作流外化与封装复盘”）。
4. **为每个主题簇编写枢纽 H2**：该 H2 汇总该簇所有节点，并提供 `*参见：……*` 列表。
5. **为每个主题簇编写其余 H2**：每个 H2 聚焦单一子问题，给出独立论证。
6. **排列顺序**：按逻辑链（问题严重性由高到低，或认知发生的时间顺序）组织全文。
7. **裁剪与强化**：删除与三大领域无关的段落；为每个 H2 补充至少一项具体数据或对比实验。
8. **合规检查**：确认无序号、无标签词、无地域/身份指向、无 H3、枢纽链接完整。

## 检查清单（生成后自检）

- [ ] 全文是否只有一个 H1？
- [ ] 是否全部使用 H2，无更低级别标题？
- [ ] 每个 H2 标题是否无序号、无标签词，且为独立可引用的名词短语？
- [ ] 每个主题簇的第一个 H2 是否包含指向该簇所有其他 H2 的显式链接？
- [ ] 是否有直接提及特定地域、职业身份或年龄段？
- [ ] 每个 H2 是否包含至少一处具体数据或可验证的细节？
- [ ] 整体语言是否简明、无修饰性废话，逻辑闭环？
