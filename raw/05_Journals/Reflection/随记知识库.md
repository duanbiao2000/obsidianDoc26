**Commonplace book** 在笔记语境中通常指“摘录本／随记知识库”：把阅读、观察和生活中值得保留的引文、事实、灵感、问题与材料，按个人兴趣收集起来，供日后思考、写作和查阅。它不是日记；重点不是按日期记录经历，而是有选择地保存“以后可能有用或值得反复咀嚼的东西”。 [en.wikipedia](https://en.wikipedia.org/wiki/Commonplace_book)

## 它的核心定位

可以把它理解为一个**个人策展式资料库**，介于读书摘抄、灵感仓库和写作素材库之间。历史上常按主题标题归类；John Locke 还设计过用索引快速定位条目的方法，目的都是让素材可以被再次找到和调用。 [publicdomainreview](https://publicdomainreview.org/collection/john-lockes-method-for-common-place-books-1685)

典型条目可以包括：

- 一本书里精确、有力量的段落
- 你自己的批注：为什么这段话重要、同意或反对什么
- 文章、播客、视频中的论点或例子
- 写作题材、研究问题、术语解释
- 日常观察、对话片段、可复用的代码／工作流思路

关键不在于“什么都存”，而在于**主观筛选**：它应当反映你的问题意识和品味，而非复制整个互联网。 [fabric](https://fabric.so/learn/commonplace-book)

## 先掌握的概念

| 概念 | 含义 | 与 commonplace book 的关系 |
|---|---|---|
| **摘录（excerpt）** | 保留原文中值得引用的片段 | 最传统、最常见的内容；须保留出处 |
| **来源／引文信息（provenance / citation）** | 作者、标题、链接、页码、时间点等 | 决定素材未来能否核验、引用和回到上下文；不要只存一句“孤立金句” [fabric](https://fabric.so/learn/commonplace-book) |
| **自己的回应（annotation）** | 对材料的解释、质疑、联想、用途说明 | 让“收藏”变成思考，例如写下“这可解释某个 agent workflow 的失败模式” [fabric](https://fabric.so/learn/commonplace-book) |
| **主题标签与索引（tags / index）** | 用关键词、主题页或页码建立检索入口 | 解决以后“记得记过，但找不到”的问题；不必一开始分类很细 [cc.lutherclassical](https://cc.lutherclassical.org/winter-2025/the-classical-art-of-keeping-a-commonplace-book/) |
| **再发现（retrieval / review）** | 定期浏览、搜索并把旧材料用于新项目 | 笔记价值主要在重访和复用中产生，而不只是记录 [fabric](https://fabric.so/learn/commonplace-book) |
| **再语境化（recontextualization）** | 将旧摘录放入新的问题、文章或项目中重新理解 | 是从“资料库”走向“创作与研究”的关键能力 |

## 易混淆的方法

| 方法 | 主要单位 | 主要目标 | 与 commonplace 的区别 |
|---|---|---|---|
| **Commonplace book** | 摘录、材料、观察、短评 | 积累可回看的智识素材 | 宽松、个人化，可混合多种内容 |
| **日记（journal/diary）** | 一天或一段经历 | 记录事件、感受与自我反思 | 以时间顺序和个人经历为主，而非主题素材 [en.wikipedia](https://en.wikipedia.org/wiki/Commonplace_book) |
| **Zettelkasten（卡片盒笔记法）** | 一张只表达一个可独立理解的想法的笔记 | 建立想法网络，服务研究与写作 | 更强调原子化、用自己的话重述、双向链接和可发展的论证网络 |
| **读书笔记／文献笔记** | 围绕一本书或一篇论文 | 理解、总结某个来源 | 范围更窄；可作为 commonplace 的输入 |
| **Second brain** | 资料、任务、项目、成果的完整系统 | 个人信息与行动管理 | 是较宽的现代生产力框架；commonplace 更偏阅读、思想和素材收集 |

不要把它们当作互斥类别。一个很实用的流程是：**阅读时做文献笔记 → 精选少量内容进入 commonplace → 发现有发展潜力的观点时，改写成 Zettelkasten 永久笔记 → 用于文章、视频脚本或项目文档。** commonplacing 本来就服务于后续检索和写作。 [cc.lutherclassical](https://cc.lutherclassical.org/winter-2025/the-classical-art-of-keeping-a-commonplace-book/)

## 最小可行做法

如果你用 Obsidian，可以先避免复杂模板：每条笔记只写四项即可。

```markdown
# 一个明确的标题或问题

> 原文摘录（尽量短）

- 来源：作者 / 作品 / 链接 / 页码或时间戳
- 我的回应：它为何重要？和什么已有笔记或项目相连？
- 标签：#AI-agents #writing
```

例如，不要只存“某模型会规划不等于会执行”；再补一句：**“可用于解释工具调用型 agent 中 planner 与 executor 应分别评测。”** 前者是素材，后者才开始成为你能在技术文章、视频脚本或项目设计中复用的知识。

## 三条实践原则

- **来源优先**：任何可引用内容都记录作者、作品、链接及页码／时间戳；这是未来验证和准确再利用的基础。 [fabric](https://fabric.so/learn/commonplace-book)
- **摘录后写一句自己的话**：回答“我为什么保留它”，否则它通常会变成很难再次使用的收藏夹。 [fabric](https://fabric.so/learn/commonplace-book)
- **保持轻量、定期回看**：先用搜索、标签或简单索引即可；分类体系应随材料自然长出来，而不是先设计一套庞大的目录。 [eadeverell](https://www.eadeverell.com/commonplace/)
