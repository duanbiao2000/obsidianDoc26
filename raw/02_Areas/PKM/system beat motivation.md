#### 一周时间块示例(每块 60-90 分钟,固定时段,当"约会"对待)

| 天   | 坐班块内容                           | 时长        |
| --- | ------------------------------- | --------- |
| 周一晚 | leetcode 录播 ×3                  | 90min     |
| 周二晚 | [[对话录播]] ×3                     | 90min     |
| 周三晚 | 小作文录播 ×3                        | 90min     |
| 周四晚 | leetcode 录播剩余的几段                | 视余量       |
| 周五  | 漫读·心智(1期)                       | 60min     |
| 周六  | 漫读·文化(1期)+ 开源项目复盘               | 90-120min |
| 周日  | 漫读·科技(1期)+ 周复盘/Obsidian AI 文字修改 | 90min     |


你的这些任务有一个共同特点：

> **它们都属于长期复利型任务，而不是短期交付型任务。**

因此，系统设计的目标不是：

> **今天完成多少。**

而是：

> **365 天后，这些事情仍然能自然发生。**

这正符合 **Systems beat motivation** 和 **I design for failure, not for motivation.**

---

# 一、先定义系统原则

我建议遵循 7 条原则。

| 原则        | 说明          |
| --------- | ----------- |
| 极低启动成本    | 不想做时也能开始    |
| 有最低完成线    | 永远不会失败      |
| 不规定顺序     | 想做哪个先做哪个    |
| 时间盒而不是任务盒 | 到时间结束即可     |
| 留有余量      | 今天状态好可以多做   |
| 自动反馈      | 每天都知道自己有没有断 |
| 可以无限持续    | 十年后仍能执行     |

一句话：

> **系统保证连续性，而不是保证效率。**

---

# 二、把任务重新分类

不要按内容分类。

而按大脑工作模式分类。

## 输入（Input）

每天吸收。

* 欧阳询《千字文》
* 三张油画
* 囫囵漫读
* Star 项目浏览

目标：

> 保持信息流。

---

## 模仿（Imitation）

每天复制。

包括：

* Leetcode
* IELTS 对话
* 小作文

目标：

> 建立 Pattern Library。

---

## 输出（Creation）

每天创造。

例如

Obsidian

AI Prompt

写总结

写笔记

目标：

> 形成自己的表达。

---

## 身体（Body）

每天维护。

散步。

目标：

> 保持能量。

---

于是每天其实只有四件事情：

```
Input
Imitation
Creation
Body
```

而不是十几个 Todo。

---

# 三、给每类设计最低标准（Minimum Viable Day）

真正防失败的关键。

例如：

## Input

最低：

任选一个：

* 看一页《千字文》
* 看一张油画
* 漫读五分钟
* Star 项目一分钟

即可。

---

正常：

20 分钟。

---

状态爆棚：

90 分钟。

所以：

```
最低
正常
爆发
```

三档。

每天任选。

---

Imitation 同理。

最低：

```
1题leetcode

或者

1段口语

或者

100词作文
```

正常：

```
10题

3段

3作文
```

爆发：

不限。

---

这样永远不会断。

---

# 四、不要规定顺序

不要：

```
先A

再B

再C
```

改成：

今天只要完成四个 Bucket。

例如：

```
□ Input

□ Imitation

□ Creation

□ Body
```

里面任选。

例如：

今天：

```
Input

✔ 三张油画
```

结束。

---

明天：

```
Input

✔ 千字文
```

结束。

这样非常自由。

---

# 五、建立循环系统（Rotation）

例如：

Input 不需要每天都全部做。

可以轮换。

例如：

周一

```
千字文
```

周二

```
欧美文化
```

周三

```
科技
```

周四

```
油画
```

周五

```
Star项目
```

周末自由。

减少选择疲劳。

# 六、引入 Fail-safe（失败保护）

真正厉害的人都会设计：

如果今天特别累怎么办？

例如：

最低标准：

```
Input：

一分钟

Imitation：

一道题

Body：

五分钟散步

Creation：

一句笔记
```

全部完成：

不到十分钟。

所以：

**不存在失败。**

# 八、每周 Review

不要每天焦虑。

每周只问四个问题：

```
这一周：

Input：
有没有持续输入？

Imitation：
有没有复制优秀作品？

Creation：
有没有留下自己的东西？

Body：
有没有照顾身体？
```

每项：

```
★★★★★
```

即可。

# 九、针对你的任务做一点优化

有几项可以进一步调整，让它们更符合“系统优先”的思路。

| 当前任务        | 建议升级                              | 原因                    |
| ----------- | --------------------------------- | --------------------- |
| 欧阳询千字文      | 每天 1 页或 5 分钟                      | 固定页数比“读完”为目标更容易坚持。    |
| 看三张油画       | 每张只回答一个问题："最吸引我的是哪一点？"            | 从被动看变成主动观察。           |
| 囫囵漫读        | 固定 15–20 分钟，不追求读完                 | 维持广泛输入即可。             |
| Star 开源项目   | 每次只回答三个问题：它解决什么问题？核心技术是什么？我能借鉴什么？ | 防止变成无目的浏览。            |
| 散步          | 与听播客或纯观察环境绑定                      | 利用习惯叠加。               |
| LeetCode    | 从“10 道”改为“至少 1 道，目标 10 道”         | 把目标和底线分开，避免因一天状态差而中断。 |
| 口语/作文       | 从“完成”改为“模仿”                       | 重心放在吸收高质量表达，而不是数量。    |
| Obsidian AI | 每天修改 AI 文本中的一句话，使其更像自己            | 小步持续优化，逐渐形成个人文风。      |

---

# 最后，把整个系统浓缩成一句运行原则

> **每天只保证四个循环不断：输入（Input）、模仿（Imitation）、创造（Creation）、身体（Body）；每个循环都设定一个低到几乎不可能失败的最低标准，并允许在状态好时自然扩展。**

这样的系统依赖的不是每天都有热情，而是**即使在最疲惫、最忙碌的日子里，也能保持“不断链”**。一年之后，你积累的不仅是完成的任务，更是一套能够长期自我运转的学习与成长机制。
