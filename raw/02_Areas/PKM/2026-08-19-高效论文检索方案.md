有，而且对你而言，**不该找一个“完整替代 researchpooler”的单体项目**，而应采用现代化组合：**Zotero 管本地资产，OpenAlex/Semantic Scholar 管发现与引文图，PaperQA 管全文问答，MCP 把这些能力接进 Claude Code 等 Agent**。这比 researchpooler 那种“抓会议网页 + pickle + LDA”的早期架构强得多，也更贴合你当前 Obsidian、PaperMemory 和 Agent 工作流。 [github](https://github.com/future-house/paper-qa)

## 最推荐的项目

| 项目 | 主要用途 | 相对 researchpooler 的升级 | 适合度 |
|---|---|---|---|
| [PaperQA](https://github.com/Future-House/paper-qa) | 对论文 PDF 库进行带依据的问答与研究 | Agentic RAG、科学文献优化、支持 PDF/文本/Office/代码，而非关键词脚本检索。 [github](https://github.com/future-house/paper-qa) | **最高：已有本地 PDF 时** |
| [Mosaic](https://github.com/szaghi/mosaic) | 检索、发现、下载、比较并映射引文关系 | 单命令聚合 21 个来源，且面向“找缺口、比方法、看引文图”的研究任务。 [github](https://github.com/szaghi/mosaic) | **最高：探索新方向时** |
| [OpenAlex Research MCP](https://github.com/oksure/openalex-research-mcp) | 给 Claude/Codex 等 Agent 接学术检索 | 通过 MCP 让 Agent 直接访问论文、作者、机构等开放学术目录，目标就是文献综述、趋势分析和研究版图映射。 [github](https://github.com/oksure/openalex-research-mcp) | **最高：你的 Agent 环境** |
| [Scientific Papers MCP](https://github.com/benedict2310/Scientific-Papers-MCP) | 多来源实时查论文 | 覆盖 arXiv、OpenAlex、PMC、Europe PMC、bioRxiv/medRxiv、CORE 等六类来源。 [github](https://github.com/benedict2310/Scientific-Papers-MCP) | **高：需要跨库查找时** |
| [A.R.I.A.](https://github.com/lifan0127/ai-research-assistant) | Zotero 内的 LLM 论文助手 | Zotero 插件，直接在你的文献管理中心调用 LLM 和引用条目。 [github](https://github.com/lifan0127/ai-research-assistant) | **中高：Zotero 内阅读时** |

## 怎么选

### 1. 你要“读自己的论文库”

选 **PaperQA**。

它解决的是：把本地论文、技术文档和项目资料变成一个能追溯来源的问答库。它也能处理源代码，所以除了论文，你可以把 LLM 推理框架文档、GitHub README、实验记录一起纳入同一个研究空间。 [github](https://github.com/future-house/paper-qa)

不过，PaperQA 的定位不是替你发现最新论文；它擅长的是**你已收集内容的深读、交叉提问、证据定位**。

### 2. 你要“自动发现相似论文和研究脉络”

选 **Mosaic**，或自己基于 OpenAlex + Semantic Scholar 组合。

Mosaic 比 researchpooler 更接近它当初想成为的样子：统一多来源检索、下载、比较方法、发现空白、映射引用关系。 [github](https://github.com/szaghi/mosaic)
底层数据源建议分工：**Semantic Scholar** 偏相似论文和引用图，**OpenAlex** 偏大范围检索、开放获取 PDF 链接和跨学科元数据；已有可复用的 Agent skill 把两者与 OpenReview、Crossref 按这一职责组合起来。 [github](https://github.com/findalexli/ai-scientist-v3/blob/main/.claude/skills/search-papers/SKILL.md)

### 3. 你要“让 Claude Code 自动帮我做调研”

首选 **OpenAlex Research MCP**；若你希望覆盖预印本和生医库，则选 **Scientific Papers MCP**。

你可以让 Agent 执行这样的高阶任务：

```text
检索 2024 年后关于 test-time scaling 的 LLM 推理论文；
按引用量、开源代码、评测数据集过滤；
找出与我 Zotero 库中现有笔记最相近、但尚未收藏的 15 篇；
为每篇生成一张 Obsidian 文献卡片，并标注其方法、结论、局限与可复现实验入口。
```

OpenAlex MCP 支持按年份检索论文、按 DOI 找论文、查询作者/概念和做基础分析；这正适合让 Agent 取代 researchpooler 的 Stage 3/4。 [github](https://github.com/skazo4ny/openalex-mcp-tool)

## 适合你的落地架构

```text
OpenAlex / Semantic Scholar / arXiv / OpenReview
                 ↓
         MCP / CLI 检索层
                 ↓
    下载 OA PDF + 元数据去重 + BibTeX
                 ↓
       Zotero（唯一文献资产库）
                 ↓
PaperMemory → Markdown → Obsidian 文献笔记
                 ↓
      PaperQA / 本地 RAG（跨论文深度问答）
                 ↓
 Claude Code / Codex：研究报告、趋势与选题分析
```

你已经把 PaperMemory 数据导出为 Markdown 并集成到 Obsidian，所以最小增量方案是：**不迁移已有系统，只在发现层加 OpenAlex MCP，在理解层加 PaperQA**。

## 一句话建议

- **马上部署一个：**`openalex-research-mcp`，因为它最容易接入你已有 Claude Code / MCP 工作流。 [github](https://github.com/oksure/openalex-research-mcp)
- **论文库开始变大后再加：**PaperQA，用于真正的跨 PDF 证据问答。 [github](https://github.com/future-house/paper-qa)
- **如果要做研究雷达/选题发现产品：**优先评估 Mosaic，再考虑自己用 OpenAlex、S2、Zotero 和 Obsidian 拼一个可控的本地优先流水线。 [github](https://github.com/szaghi/mosaic)
