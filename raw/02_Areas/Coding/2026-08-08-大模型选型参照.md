## 编程能力

`Coding` 一栏主要评估模型在真实软件工程任务中的表现，如理解代码库、改 Bug、编写代码、运行命令、完成测试。

| 指标 | 它在测什么 | 对选型的帮助 |
|---|---|---|
| SWE-Bench Verified / Pro | 修复真实 GitHub 项目的 issue | 做真实项目改造、Bug 修复，参考价值最高 |
| TerminalBench 2.1 | 在终端内完成多步工程任务 | 适合判断 Claude Code、Codex、Orca 等 agent 场景 |
| SWE Atlas 系列 | 代码定位、代码问答、测试编写、修复效率 | 区分“能写代码”与“能读懂陌生大型项目” |
| LiveSQLBench | 数据库与 SQL 实战问题 | 数据处理、分析、SQL 自动化时参考 |
| VIBE-V2 / SVG-Bench | 前端交互、视觉或 SVG 生成 | 网页 UI、可视化资产生成时更有意义 |

## 给你的选型策略

你目前可通过 Ollama Cloud 在 MiniMax M3 与 DeepSeek 系列间切换，且 Free 层同时只能使用一个云模型。最有效的做法不是依据一张总表押注，而是按任务切换：

| 任务 | 优先尝试 | 使用方式 |
|---|---|---|
| Python 自动化、终端、Agent coding | MiniMax M3 | 给明确目标、仓库约束、测试命令和验收标准 |
| 日常问答、中文写作、资料总结 | DeepSeek V4 Flash | 更省额度，适合高频轻量交互 |
| 长文档/图片/截图/PDF 解析 | MiniMax M3 | 先上传材料，再要求引用页码、表格或图中具体证据 |
| 高风险重构、疑难 Bug | M3 起草，第二模型复核 | 要求运行测试、解释 diff、逐项验证假设 |
| 短小脚本、正则、命令解释 | DeepSeek V4 Flash | 速度优先，避免使用高消耗模型 |
| 多 Agent 并行开发 | M3 + Orca / Claude Code 类工具 | 每个任务单独 worktree，最终人工 review 和合并 |

特别实际的一点：在你的免费档位，**M3 的 benchmark 优势只有在任务足够复杂时才值得消耗一次 cloud slot**。对于翻译、普通总结、几行脚本或常规问答，先用 DeepSeek Flash；遇到跨文件工程、工具调用、复杂文档/图像理解或 Agent 工作流，再切到 M3，会更划算。
