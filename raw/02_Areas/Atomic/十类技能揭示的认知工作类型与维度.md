# 十类技能揭示的认知工作类型与维度

**核心**：一组具体技能画像可提炼出稳定的"认知工作类型"分类法——编码实现、系统架构、深度研究、精英调试、产品原型、自主执行、STEM 教学、代码评审、通用综合等；并可沿"自主度""领域聚焦""输出风格"等维度切片。类别比具体产品更持久。

**为什么 / 证据**（从十类技能归纳）：
> 十类画像覆盖：production-engineering / pair-programming / system-architecture / truth-seeking-research / elite-debugging / product-prototyping / autonomous-coding / stem-first-principles / code-review / knowledge-worker-general。
可归纳出维度：① 自主度（pair 低 → autonomous 高）② 领域（通用 ↔ 专域如 STEM/code）③ 输出（代码 / 研究结论 / 原型 / 评审意见）④ 交互密度（实时结对 ↔ 一次性综合）。

**边界 / 反例**：
- 看似重叠（如 autonomous-coding 与 production-engineering 都写码）是因为把分类当成**扁平清单**；一旦改为**正交维度**（意图 × 自主度 × 领域 × 输出 × 交互密度），每个任务落到唯一坐标，重叠自然消失。两者只在同一意图下靠"自主度/关注点"区分（见 [[Agent 应按触发条件动态路由到最匹配的技能画像]] 裁决规则）。
- 类别本身随工具演进重组；"十类"是可迁移的抽象，非永久真理（类比 [[Harness框架可归四类且类别比具体产品更持久]]）。

**我的判断**（个人层 / 应用）：
- 我评估任何"Agent 角色库"先看它覆盖了哪些认知工作类型、在哪些维度上有意区分；这比记具体角色名更有用，因为角色会随产品换代。
