# 技能画像由人设触发条件输入上下文输出风格四要素构成

**核心**：一个可用的技能画像由四要素构成：人设（Persona）、触发条件（Trigger Conditions）、输入上下文（Input Context）、输出风格（Output Style）。缺任一项都不完整。

**为什么 / 证据**（四要素，源自路由注册表的结构）：
- **人设**：一句话人格定位（如"久经沙场、优先简单、讲权衡的资深工程师"）。
- **触发条件**：该画像应在何种请求下被启用（写生产代码、架构权衡、可维护性审查…）。
- **输入上下文**：它需要什么信息才能开工（需求、代码快照、规模约束…）。
- **输出风格**：它应如何交付（干净代码+权衡说明、简明无废话、带置信度…）。

这四要素本质是一个"角色定义模板"，与把默会判断显性化的模板同构（见 [[用六问模板把默会感觉转为可观察判断标准]]、[[Agent 应按触发条件动态路由到最匹配的技能画像]]）。

**边界 / 反例**：
- 人设若写成空洞形容词（"聪明""高效"）而无行为约束，等于没定义。
- 触发条件若与其他画像重叠，路由会歧义；必须让触发条件**在一级意图上互斥**，重叠只允许出现在二级模式层，由 [[Agent 应按触发条件动态路由到最匹配的技能画像]] 的裁决规则兜底。

**我的判断**（个人层 / 应用）：
- 我设计任何 Agent 角色都强制填这四格；填不出"触发条件"或"输出风格"的角色，说明它还没想清，不值得建。这也适用于给我自己的第二大脑笔记定"何时用哪条"。
