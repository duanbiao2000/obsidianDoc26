# 📇 闪卡设计指南：从任意笔记快速生成高质量卡片
(Obsidian的spaced repetition插件规则)

---

## 一、判断生成卡片类型的核心规则

### 🔍 内容识别 → 卡片类型映射表

| 笔记中出现的内容特征 | 识别信号（关键词/结构） | 生成卡片类型 | Separator 语法 |
|---|---|---|---|
| **定义/概念** | "是指"、"定义为"、"即"、"称为" | 单行正向卡 | `概念 :: 定义` |
| **双向关联**（术语↔解释） | 专有名词+解释段落 | 单行反向卡 | `A ::: B` |
| **列举/要素** | "包括"、"分为"、"有以下几点"、数字列表 | 多行正向卡 | `问\n?\n答` |
| **因果关系** | "因为…所以"、"导致"、"原因是" | 单行正向卡（因→果 & 果→因各一张）| `:: ` |
| **对比/区别** | "与…相比"、"区别在于"、"vs" | 多行正向卡 | `?\n` |
| **公式/数据** | 数字、符号、单位、等号 | Cloze 挖空 | `==数值==` |
| **步骤/流程** | "第一步"、"首先…然后…最后"、有序列表 | 多行正向卡（完整步骤） | `?\n` |
| **举例说明** | "例如"、"比如"、"以…为例" | Cloze 挖空（挖掉例子） | `{{例子}}` |
| **判断/结论** | "因此"、"总结"、"结论是" | 单行正向卡 | `:: ` |
| **人名/时间/地点** | 专有名词、年份、地名 | Cloze 挖空 | `==名称==` |

## 二、自动生成的决策树

```
读取笔记段落
    │
    ├─► 是否含"定义/是指/称为"？
    │       ├─ 是 → 单行正向卡（Q=概念, A=定义）
    │       └─ 是双向关联 → 单行反向卡
    │
    ├─► 是否含数字/公式/专有名词？
    │       └─ 是 → Cloze 挖空（挖关键值）
    │
    ├─► 是否含有序列表/步骤？
    │       └─ 是 → 多行正向卡（问=流程名，答=完整步骤）
    │
    ├─► 是否含因果/对比结构？
    │       ├─ 因果 → 正向卡（因→果）+ 反向卡（果→因）
    │       └─ 对比 → 多行正向卡（列出对比维度）
    │
    └─► 段落较长但无明显结构？
            └─ 提取核心句 → Cloze 挖掉关键词
```

## 三、卡片类型的认知层次对应（布鲁姆分类法）

```
【记忆层】─────────────────── Cloze 挖空、单行正向卡
    填空：中国首都是 ==北京==
    问答：光速 :: 约3×10⁸ m/s

【理解层】─────────────────── 单行/多行正向卡
    用自己的话解释：什么是量子纠缠？
    ?
    两粒子的量子态相互关联，测量一个
    瞬间影响另一个，不受距离限制。

【应用层】─────────────────── 多行正向卡（情境题）
    给定场景：当HTTP请求返回403时，应该怎么排查？
    ?
    1. 检查鉴权Token是否过期
    2. 确认当前用户是否有该资源权限
    3. 查看服务端访问日志

【分析层】─────────────────── 多行反向卡（双向推导）
    对比 TCP 和 UDP 的核心差异
    ??
    TCP: 有连接、可靠、有序、慢
    UDP: 无连接、不可靠、无序、快

【评价/创造层】────────────── 多行正向卡（开放判断题）
    为什么说"过早优化是万恶之源"？
    ?
    因为在需求不明时优化会锁死架构，
    导致后期更大的重构成本…
```

## 四、一篇笔记的卡片比例设计

### 📊 推荐比例（适合"全面掌握"目标）

```
┌─────────────────────────────────────────────┐
│           一篇笔记的卡片构成               │
├──────────────┬──────────┬───────────────────┤
│  卡片类型    │  占比    │  对应认知目标     │
├──────────────┼──────────┼───────────────────┤
│ Cloze 挖空   │  30%     │ 关键词/数值记忆   │
│ 单行正向卡   │  25%     │ 概念定义理解      │
│ 单行反向卡   │  10%     │ 双向关联记忆      │
│ 多行正向卡   │  25%     │ 流程/列举/应用    │
│ 多行反向卡   │  10%     │ 深度双向推导      │
└──────────────┴──────────┴───────────────────┘
```

### 📐 按笔记类型调整比例

| 笔记类型 | Cloze | 单行正向 | 单行反向 | 多行正向 | 多行反向 |
|---------|-------|---------|---------|---------|---------|
| **概念/理论笔记** | 20% | 35% | 15% | 20% | 10% |
| **事实/记忆笔记** | 50% | 30% | 10% | 10% | 0% |
| **步骤/流程笔记** | 15% | 15% | 5% | 55% | 10% |
| **对比/分析笔记** | 10% | 20% | 20% | 20% | 30% |
| **混合笔记** | 30% | 25% | 10% | 25% | 10% |

## 五、自动生成的实操规则（可直接给 AI 使用的 Prompt）

```
你是一个 Obsidian Spaced Repetition 闪卡生成器。
请分析以下笔记内容，按照这些规则生成闪卡：

【规则】
1. 定义/概念 → 生成单行正向卡：`概念 :: 定义内容`
2. 专有名词/数值/关键词 → 用 ==挖空== 生成 Cloze
3. 双向关联术语 → 生成单行反向卡：`A ::: B`
4. 有序步骤/列举 → 生成多行正向卡（?分隔）
5. 对比/区别内容 → 生成多行反向卡（??分隔）
6. 因果关系 → 生成两张单行正向卡（正向+逆向各一张）

【比例要求】
- Cloze 约占 30%
- 单行正向卡约占 25%
- 多行正向卡约占 25%
- 反向卡合计约占 20%

【质量原则】
- 每张卡只考一个知识点（最小信息原则）
- 答案不超过 3 行
- 问题必须能独立理解，不依赖上下文
- 避免模糊问题（如"解释一下XX"这类太宽泛）

请直接输出符合 Spaced Repetition 插件格式的 Markdown 内容。
```

## 六、质量控制：好卡 vs 坏卡 对比

### ❌ 坏卡示例

```markdown
# 太宽泛
什么是机器学习？ :: 机器学习是一种人工智能技术，
它使用算法让计算机从数据中学习，而不需要明确编程…（答案太长）

# 依赖上下文
它的作用是什么？ :: 提取特征（问题不独立）

# 一卡多知识点
神经网络的层数和激活函数有哪些，各有什么作用？
?
层数：输入层、隐藏层、输出层
激活函数：ReLU、Sigmoid、Tanh…（考了太多）
```

### ✅ 好卡示例

```markdown
# 精准定义
监督学习 :: 使用带标签数据训练模型，让其学会输入→输出的映射关系

# 数值挖空
ReLU 激活函数的公式为 ==f(x) = max(0, x)==

# 拆分多知识点（拆成3张）
ReLU 的优点 :: 计算简单、缓解梯度消失问题
Sigmoid 适用场景 :: 二分类输出层
Tanh 与 Sigmoid 的区别 ::: Tanh 输出范围 [-1,1]，Sigmoid 输出 [0,1]

# 流程卡（只考一个流程）
梯度下降的核心步骤
?
1. 计算当前参数下的损失值
2. 对参数求偏导（梯度）
3. 沿梯度反方向更新参数
4. 重复直到收敛
```

## 七、完整示例：一段笔记 → 生成闪卡

### 原始笔记段落

> TCP 协议是一种面向连接的、可靠的传输层协议。建立连接需要经过三次握手：
> 第一次：客户端发送 SYN；第二次：服务端回复 SYN+ACK；第三次：客户端发送 ACK。
> 与 UDP 相比，TCP 速度较慢但数据不会丢失，适合文件传输、网页浏览等场景。

### 生成的闪卡（8张）

```markdown
TCP 协议 :: 面向连接的、可靠的传输层协议

TCP 建立连接需要 ==三次== 握手

TCP 三次握手的过程
?
1. 客户端 → 服务端：SYN
2. 服务端 → 客户端：SYN + ACK
3. 客户端 → 服务端：ACK

TCP vs UDP 的核心区别
??
TCP：有连接、可靠、较慢，适合文件传输/网页
UDP：无连接、不可靠、较快，适合视频流/游戏

TCP 适用场景 :: 文件传输、网页浏览（数据完整性要求高）

三次握手第一步，客户端发送的是 ==SYN==

为什么 TCP 比 UDP 慢？ :: 需要建立连接、确认应答、重传机制，开销更大

TCP 可靠性的保障机制 :: 确认应答（ACK）+ 超时重传 + 流量控制
```
