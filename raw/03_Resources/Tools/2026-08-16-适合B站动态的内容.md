## 最推荐：发布收件箱

建立一个本地“动态收件箱”，把每条候选动态做成一张 Markdown 卡片，放在 Obsidian 或一个固定目录里。你只需复制一条、在 B 站客户端/创作中心粘贴、补图并发布；这保留了你的最终判断，也能让你高频输出。

建议字段：

```md
---
status: draft
publish_window: 12:30
topic: Affinity / AI / 制作复盘
assets:
  - /path/to/image-01.png
source_url:
---

一句强钩子（首行）

正文：3–6 行，说明观点、过程或结论。

问题：你会怎样做？
#标签1 #标签2
```

对于你这类技术内容，可以把动态固定成四类：**视频预告、制作过程、工具发现、观点/问题**。这样不用每次从零想选题，直接从项目日志、Git commit、剪辑时间线或阅读笔记中挑一个“可公开切片”即可。

## 快速输入方式

| 环节 | 最快做法 | 作用 |
|---|---|---|
| 捕捉灵感 | 手机语音输入或 Obsidian QuickAdd | 先记录，不编辑 |
| 生成初稿 | 本地脚本调用 LLM | 输出 2–3 个短版本 |
| 审核 | 你人工选一个 | 确保事实、语气、配图与链接正确 |
| 发布 | B 站官方 App/创作中心粘贴发布 | 保留人工最后确认 |
| 归档 | 标记 `published` 并写入链接 | 以后能复盘内容表现 |

你偏好本地优先和脚本化工作流，可以用 Python + `uv` 做一个命令：从当天 Obsidian 日志或项目变更中取素材，调用模型生成 `drafts/2026-08-16-主题.md`，再打开文件让你复制发布。

## 30 秒模板

**视频预告**
```text
这期我想解决一个具体问题：____。

核心结论是：____。
视频里我会演示：____。

今晚/明天发布。你最想看哪一部分？
```

**制作复盘**
```text
刚解决了一个很烦的问题：____。

原来的做法：____。
现在的做法：____。
最大收益：____。

如果你也在做 ____，这个坑可以绕开。
```

**工具发现**
```text
今天试了 ____。

它真正有用的不是“功能多”，而是：____。
适合：____。
不适合：____。

我准备把它用在 ____。
```

**观点提问**
```text
一个最近在想的问题：

____。

我的暂时答案是：____。
但我还不确定 ____，你们会怎么处理？
```

## 自动化边界

可以自动化**选题归集、草稿生成、配图导出、发布提醒、发后归档和数据汇总**；不要做无人值守的自动发布、自动评论、自动点赞或批量互动。平台规则通常禁止误导、重复骚扰式发布和破坏账号/平台安全的自动化行为，且内容发布本身仍需要你对版权、事实和表达负责。 

最实用的形态不是“机器人代运营”，而是一个 **一键生成草稿 + 人工确认发布** 的发布台：既快，也不会失去你自己的表达风格。
