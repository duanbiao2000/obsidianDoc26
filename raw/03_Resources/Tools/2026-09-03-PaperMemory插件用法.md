这个 **PaperMemory** 是一个浏览器扩展，定位是“轻量、自动化的论文阅读记录器”。它不是要替代 Zotero，而是在你平时逛 arXiv、OpenReview、NeurIPS、ACL、IEEE、Springer 等论文页面时，自动把你打开过的论文收集起来，并补齐代码仓库、正式发表版本、BibTeX、Markdown 链接等信息。数据默认保存在本机，也能导出 JSON 和 BibTeX。[[github](https://github.com/vict0rsch/PaperMemory)]

## 它具体做什么

你打开一篇支持来源的论文，它会自动识别并建立一条记录；之后可以搜索、加标签、写评论，并关联发现到的代码仓库。它还支持通过 Papers with Code 的接口寻找实现仓库，并尝试将 arXiv 预印本和后续正式发表版本匹配起来。

|功能|实际效果|
|---|---|
|自动记录浏览过的论文|减少“这篇论文我以前在哪见过”的重复检索|
|自动找代码仓库|对做 AI 工程、复现实验特别实用，读论文时更快落到可运行项目|
|预印本匹配正式发表版本|引用、做笔记或讲解时，更容易找到 NeurIPS、ICLR、ACL、ICML 等正式版本|
|一键复制 BibTeX|放入 Zotero、LaTex 文稿或文献库时少一次手工整理|
|一键复制 Markdown 链接|很适合直接贴进 Obsidian 笔记、GitHub Issue/PR、README|
|规范化 PDF 标题和下载文件名|不再积累 `1706.03762.pdf` 这类难找的文件，下载名可包含论文标题|
|自动/规则化标签|可按标题、作者的正则规则自动打标签，例如 `LLM`、`agent`、`RAG`|
|本地导出与 Gist 同步|本地优先；也可借 GitHub Gist 在多设备之间同步论文元数据|

## 对你最有价值的部分

你的工作流已经有 **浏览器研究 → Zotero → Obsidian → GitHub/代码实验** 这条链路。PaperMemory 最适合作为其间的“**论文发现收件箱**”，而不是作为最终文献库。

### 1. 降低研究浏览的记录成本

你平时会看 LLM、Agent、MCP、推理和开源项目。大量论文阅读其实发生在“快速判断值不值得深入”的阶段；这时若必须每篇都手动导入 Zotero，会打断节奏。

PaperMemory 自动留痕后，你可以先随意探索；等周末或某个固定时间，再从它的历史记录里筛出真正值得读、下载 PDF、做深度笔记并正式导入 Zotero 的论文。这个分层可以避免 Zotero 被大量“只看了摘要”的条目污染。其项目本身也明确表示它旨在补充而非取代 Zotero 一类参考管理器。

### 2. 从论文直接走向可复现代码

对于独立开发者，论文价值往往不只在引用，而在于能否变成一个 demo、脚本、模型测试或视频选题。PaperMemory 在论文条目里尝试发现关联代码仓库，意味着你的路径可以从：

> arXiv 论文 → 找官方/社区实现 → 打开 GitHub → clone 或读取 README → 进入本地实验

缩短为更少的跳转。尤其是读模型结构、agent 框架、视觉或音频处理方法时，这会比纯 Zotero 流更贴合工程实践。

### 3. 让 Obsidian 笔记更快落地

它可直接生成形如 `

```
- 
  - Tags: #agent #inference
  - Code: GitHub 链接
  - Why: 准备用于比较某个 agent memory 方案
```

这样，浏览阶段的碎片发现不会散落在浏览器书签、下载目录和聊天记录里；之后再把已读、已验证有价值的项目迁移到你的长期文献笔记或项目仓库。

## 推荐的搭配方式

**不要把它当作 Zotero 替代品，而是这样分工：**

|工具|角色|
|---|---|
|PaperMemory|自动捕获“看过或路过”的论文，快速附代码、标签、短评|
|Zotero|保存需要长期引用、管理 PDF、写正式研究笔记的精选文献|
|Obsidian|连接论文观点、实验记录、视频脚本、项目想法|
|GitHub / 本地项目|保存复现代码、比较结果、可运行原型|

一个可执行的规则是：

- **打开即自动进 PaperMemory**：零摩擦留痕
- **值得精读才进 Zotero**：PDF、批注、正式文献管理
- **要转化为输出才进 Obsidian / GitHub**：你的理解、实验、脚本和内容选题

## 需要注意

- 它的“找代码”和“预印本匹配正式版本”属于自动推断，不能保证每次正确；准备引用、复现或做视频时，仍应核对作者、会议和仓库是否官方。项目说明也表示预印本到正式发表版本不存在统一的集中数据源。
- 它的优势主要在**浏览器内的论文发现与轻管理**；如果你已经严格把每篇论文都立刻保存到 Zotero，增益会较小。
- 它支持 Chrome、Brave、Edge 和 Firefox；数据在本地，可导出 JSON/BibTeX。

对你而言，它最可能节省的是“**发现一篇有意思的 AI 论文后，忘了收藏、找不到代码、过两天又重复搜索**”这些隐性时间成本。
