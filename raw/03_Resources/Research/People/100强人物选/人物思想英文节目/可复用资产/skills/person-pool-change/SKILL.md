# Skill｜人物库变更

## 触发

用户要求新增、移出、替换、重排、改章节、改编号或升级正式人物名单版本时调用。

## 读取

1. `../../../AGENT.md`
2. `../../../00-项目交接与实时状态.md`
3. 当前正式名单（由交接文件 frontmatter 指定）
4. `../../自动化/人物库硬约束.v0.1.json`
5. `../../自动化/hook-manifest.v0.1.json`

## 本 Skill 负责的结果

- 正式名单的内容、章节、编号与版本更新；
- 每个“进 / 出 / 位置”的编辑理由，写入正式名单的版本记录；
- 机器约束配置、入口索引和实时交接状态的同步；
- 通过名单及引用校验后，才可对用户宣布完成。

## 执行步骤

1. 把用户指令拆成“确定加入 / 确定移出 / 待确认 / 仅观察”四类；
2. 若会改变人数，先保持正式名单总数符合机器约束；缺少移出决定时，按用户授权选择或先询问；
3. 按编辑逻辑放入最合适章节，不能机械占用原编号；
4. 复制/升级正式名单版本，更新标题、frontmatter、正文、比例检查和版本记录；
5. 如用户的硬性保留或排除决定变化，更新 `人物库硬约束.v0.1.json`；
6. 更新根 README、人物库 README 和实时交接文件中指向当前版本的引用；
7. 运行：

```bash
python3 可复用资产/自动化/check_people_list.py
python3 可复用资产/自动化/check_project_links.py
```

8. 调用 `handoff-close` 完成会话收尾。

## 不负责

- 不为每位候选人补写完整研究档案；那是 `episode-readiness` 的工作；
- 不将“候选池”误称为已承诺排期；
- 不绕过正式名单的版本记录，用交接文档代替内容变更。
