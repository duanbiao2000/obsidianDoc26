# 可复用资产库｜使用说明

这里存放所有会在多期节目中反复使用的**规范、模板、固定节目组件和语言资产**。本文件夹不是资料仓库：具体人物的采访、年表、脚本和素材清单必须放在 `../节目制作/EPxxx-人物名/` 中。

## 资产目录

| 文件 | 何时使用 | 产出/作用 |
|---|---|---|
| `01-栏目编辑宪章.md` | 一切选题与改稿前 | 保持频道定位、语气与伦理边界 |
| `02-人物选题评分卡.md` | 新人物提案时 | 决定是否进入选题池 |
| `03-研究与事实核查规范.md` | 资料搜集与成稿前 | 让生平、引文、影响力主张可核验 |
| `04-单集叙事与节拍模板.md` | 写大纲时 | 10–11 分钟的稳定观看结构 |
| `05-英文口播风格规范.md` | 写英文稿与试读时 | 保证英文自然、精确、可听懂 |
| `06-中文字幕与术语规范.md` | 字幕、概念卡制作时 | 让英文主讲不成为理解障碍 |
| `07-画面包装与节目组件规范.md` | 分镜和剪辑前 | 固定视觉语法、版权和节奏规则 |
| `08-制作工作流与版本管理.md` | 单集立项到归档 | 明确阶段、闸门、文件命名与状态 |
| `09-录制剪辑发布质检清单.md` | 录制前、交付前、上线前 | 防止事实、语言、音画和发布遗漏 |
| `10-B站发布与复盘规范.md` | 发布前后 | 形成标题、互动和复盘的长期机制 |
| `11-常用英文口播文案库.md` | 写脚本时 | 可直接借用的开场、转场、边界、结尾句型 |
| `12-发布节奏与选题储备规范.md` | 制定月度排期与扩频前 | 决定双周/周更条件、内容库存与并行节奏 |
| `13-单集准备材料与资料采集手册.md` | 脚本开发前 | 明确每期必须取得的材料包、权威获取路径与新鲜度方法 |
| `14-资料雷达与人物库维护规范.md` | 日常选题储备与角度锁定前 | 维护低成本资料雷达、人物池和平台陈词滥调审计 |
| `15-创作者与表演者人物开发补充规范.md` | 开发演员、导演、音乐人、运动员、设计师等人物时 | 以作品、过程与完整访谈作为等同于书/讲演的一手材料体系 |
| `16-计算机科学人物开发补充规范.md` | 开发计算机科学家、软件工程师、语言/系统设计者时 | 用技术一手材料、三层解释法、设计取舍与技术事实复核保障深度和准确性 |
| `skills/` | Agent 面对明确任务类型时 | 选择并执行某项任务的输入、产出、调用关系与验证；不重复长期规则 |
| `自动化/` | 名单、版本、EP 阶段或会话收尾的结构性检查时 | Hook manifest、机器约束和只读校验脚本；不代替编辑判断 |
| `模板/` | 每期启动时 | 可复制的项目、研究、脚本、术语、复盘、准备材料与新鲜度审计模板 |

## 资产维护规则

1. **只把跨三期以上仍有价值的内容放进来。** 一次性资料不进入资产库。
2. 每次修改规范时，在文件底部增加一行“变更记录”。
3. 模板文件始终保持空白、通用；填写后的版本必须另存到具体 EP 文件夹。
4. 固定栏目组件名称不得随意改写：`The Tension / The Text / The Test / The Limit / One Question`。
5. 若新做法与现有规范冲突，先在单集项目中试验；经至少两期验证后再升级为资产库标准。

## 使用底线

资产库旨在节省重复劳动，不用于把所有人物剪成同一种人生。**结构可以稳定，判断必须新鲜。**
