## 这一组为什么合适

八位人物刚好覆盖不同层次，而不是八个“程序员偶像”：

```text
Knuth        → 算法、写作、极长周期的精确
Kernighan    → C / Unix、教学与清晰表达
Dijkstra     → 程序推理、严谨与反便利思维
Stroustrup  → 编程语言设计、兼容性与现实妥协
Lamport      → 形式方法、分布式系统、准确性
Pike         → Unix / Go、简洁与工具哲学
Tanenbaum    → 操作系统、网络、教材与知识传承
Fowler       → 重构、架构、维护与组织协作
```

对应的叙事路径是：

> **如何思考清楚 → 如何表达清楚 → 如何设计语言和工具 → 如何理解复杂系统 → 如何长期维护系统与组织。**

这比只讲“谁创办了哪家公司”更适合节目的人物思想定位。

## 研究优先级

### 首先开发（建议进入前 12 人研究池）

1. **Donald Knuth**：技术厚度、人生方法与节目气质最强。
2. **Brian Kernighan**：英文口播特别有优势，观众容易进入技术写作和清晰思考问题。
3. **Edsger W. Dijkstra**：可建立频道“严谨但不卖弄”的思想气质。
4. **Martin Fowler**：与当代中国技术从业者、知识工作者的日常关联度很高。

### 第二梯队开发

5. **Andrew S. Tanenbaum**：适合在 Linus 之后形成系统、教育与开放学习的对话。
6. **Rob Pike**：适合 Unix / Go / 工程品味专题。
7. **Bjarne Stroustrup**：需要较好的 C++ 技术审校，但能做出极有质量的一集。
8. **Leslie Lamport**：技术密度最高，建议在建立一批技术观众后推出。

## 所有技术人物的开发前置条件

每个人在正式写稿前都必须通过：

- `可复用资产/16-计算机科学人物开发补充规范.md`
- 一手技术著作/论文/规范的实质阅读；
- 至少一份完整讲座或深度访谈；
- 一位领域熟悉者的技术事实复核；
- 一个明确技术取舍，而不只是一项“伟大发明”；
- 一个不把技术人物神化的边界段落。
