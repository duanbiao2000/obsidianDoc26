# MODULE: MOC Auto-Generator (v0.3)
# @CONTEXT: 用于 Obsidian 知识库根目录的 MOC 自动重建
# @TRIGGER: 每次执行清理“孤立笔记”或“反向链接不足”的节点
# =============================================

import os
import glob
from collections import Counter

# ------------------------------------------------------------
# 核心算法：基于阈值触发的 MOC 创建
# ------------------------------------------------------------

def scan_and_build_moc(vault_path, threshold=7):
    """
    @DECISION: 阈值设为 7 的原因
    根据 2026-07 的日志统计，单篇笔记被其他笔记引用的中位数是 3 次。
    设定阈值为 7（即中位数的 2 倍+1），是为了过滤掉“偶然关联”，
    只捕获确实具备枢纽潜质的节点。低于 7 的节点强行建 MOC 会导致碎片化。
    
    @ALTERNATIVE: 曾考虑动态百分位阈值（如前 20%）。
    但在实验中发现，当新增一批日语学习笔记后，百分位阈值会剧烈波动，
    导致已有 MOC 的频繁重构。固定阈值牺牲了部分数学美感，换取了系统的稳定性。
    """
    
    # 获取所有 Markdown 文件

    all_files = glob.glob(os.path.join(vault_path, "*.md"))

    link_counter = Counter()
    for f in all_files:

            content = file.read()
            # @LESSON: 上一版脚本使用正则 `r'\[\[(.*?)\]\]'` 贪婪匹配，
            # 导致含 `|` 别名和 `#` 标题锚点的链接解析错误（2026-08-15 故障）。
            # 本次改用更严格的非贪婪匹配，并忽略别名部分，仅取主标题。

                link_counter[link] += 1

    # 如果未来 vault 体量扩大到 1000+ 文件，全量重建耗时可能从当前 0.8s 增至 4s 以上。

# 辅助函数（标注省略以聚焦主题）
# ------------------------------------------------------------
def write_moc_to_disk(title, content):
    # @LESSON: 2026-08-20 曾因未处理 Windows 文件名非法字符导致脚本崩溃。
    # 虽当前在 MacOS 环境运行，仍保留 sanitize 函数以保兼容。
    sanitized_title = "".join(c for c in title if c.isalnum() or c in " _-")
    with open(f"{sanitized_title}.md", 'w') as f:
        f.write(content)

### 这个例子如何体现你笔记中需要的“复盘机制”？

1. **@DECISION（决策标注）**：把“为什么是 7”而非其他数字的权衡过程写死，下次如果效果不佳，你直接看这段代码就能重建当时的推理场景，而不用翻 3 天的日记。
2. **@ALTERNATIVE（替代方案标注）**：记录了“动态百分位”这条未走的路，防止未来你心血来潮想改算法时，又重新踩一遍同样的坑。
3. **@LESSON（失败教训标注）**：显式关联了历史故障（正则表达式解析错误和文件系统兼容问题）。这直接把“复盘结果”嵌入到了“执行工具”里——**下次你改脚本前，第一眼看到的就是过去的疼痛点**。
4. **@STATE（状态快照标注）**：写死了当前的文件数量（347）和预估的衰减拐点（500 文件）。这就呼应了你笔记里要求的“实证数据”，未来你可以冷酷地验证：**当文件数达到 500 时，启动耗时是否真的如预测般恶化？**
