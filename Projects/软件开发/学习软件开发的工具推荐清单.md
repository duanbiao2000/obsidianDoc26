## 核心定位

Dependencies 的强项是查看 `.exe/.dll` 的导入依赖、缺失库、模块结构，特别适合 Windows 桌面开发和排障。 它还是老牌 Dependency Walker 的现代替代方案，能更好支持新系统环境。developer.aliyun+3

## 工具清单

## 1. 依赖分析

- **Dependencies**：首选，适合看 DLL 依赖、缺失模块、Electron/Qt 识别。lucasg.github+1
- **Dependency Walker**：老工具，适合了解“经典静态依赖分析”概念，但在新系统上表现较差。cnblogs+1
- **AllDllsDependencies**：可作为补充，适合对比学习静态依赖分析思路。[developer.aliyun](https://developer.aliyun.com/article/804159)

## 2. 进程与运行时观察

- **Process Explorer**：看进程树、模块加载、句柄和线程，适合判断 Electron 多进程、服务进程等。
- **任务管理器**：最基础但够用，适合初步看进程数量和 CPU/内存占用。
- **Process Monitor**：看程序启动时读了哪些文件、注册表和 DLL，适合排障和理解启动流程。

## 3. PE 文件分析

- **PE-bear**：看 PE 头、节区、导入表，适合入门二进制结构。
- **CFF Explorer**：也常用于查看 PE 结构、资源、导入导出表。
- **Detect It Easy（DIE）**：识别编译器、打包器、壳，适合判断软件是不是 Electron、Qt、.NET 或被加壳。

## 4. 反编译与逆向入门

- **Ghidra**：免费强大，适合从机器码层面理解程序。
- **IDA Free**：经典逆向工具，适合配合 Ghidra 学习。
- **dnSpyEx**：如果是 .NET 程序，这个非常好用，能直接看反编译代码。

## 5. 调试与系统级观察

- **x64dbg**：Windows 下很常见的调试器，适合看程序运行过程。
- **WinDbg Preview**：微软官方，适合更底层的系统分析。
- **Visual Studio Debugger**：如果你本来就在学 C# 或 C++，这是最顺手的调试入口。

## 6. 打包与安装包分析

- **7-Zip**：看安装包内部结构，很多安装程序可以直接解包。
- **Inno Setup Extractor / NSIS 解包工具**：识别安装器类型并提取文件。
- **asar 工具**：如果是 Electron，可解包 `app.asar` 看前端资源。

## 学习路线

如果你的目标是“学会看懂软件怎么做出来”，推荐这个顺序：

1. **Dependencies**：先学依赖关系。
2. **Process Explorer / Process Monitor**：再学运行时行为。
3. **DIE + PE-bear**：理解文件格式和编译痕迹。
4. **Ghidra / dnSpyEx**：深入到代码层。
5. **x64dbg / WinDbg**：最后学调试和系统交互。cnblogs+2

## 一个实用搭配

如果你只想装最少的工具，我建议先装这 4 个：

- Dependencies。
- Process Explorer。
- Detect It Easy。
- Ghidra 或 dnSpyEx（二选一）。

这套组合能覆盖“它是什么、怎么跑、依赖什么、代码大概长什么样”四个层面。csdn+1
