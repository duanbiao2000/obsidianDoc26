# 道德经框架在提示词设计中的应用

## 一、核心哲学映射

```
提示词设计的根本悖论：
越精确的指令 → 越限制模型能力
越模糊的指令 → 越难控制输出

道德经的解法：
"为学日益，为道日损"
→ 不是写更多约束，而是找到最小必要结构
```

---

## 二、"无为"原则：最小必要提示

### 反面示例（过度控制）

```
❌ 过度指令化提示词：
你是一个专业助手，你必须：
1. 用中文回答
2. 回答长度在500字以内
3. 使用正式语气
4. 分三段组织内容
5. 第一段介绍背景
6. 第二段分析问题
7. 第三段给出建议
8. 不要使用表情符号
9. 引用至少两个例子
10. 结尾要有总结句
...（更多规则）
```

```
问题所在：
├── 约束相互冲突
├── 模型消耗大量token处理规则
├── 压缩了模型的推理空间
└── "物壮则老" → 过度规范导致系统僵化
```

### 道德经解法（无为而无不为）

```
✅ 最小必要结构：

[角色核心] 一句话定义本质
[情境] 必要上下文
[意图] 真实目标（非表面任务）
[空间] 明确留白

示例：
"你是一个帮助用户看清问题本质的思考伙伴。
用户正在：[情境]
真正需要的是：[深层意图]
请以你认为最有效的方式回应。"
```

---

## 三、"有无相生"：结构与留白的平衡

### 框架设计原则

```
提示词的"实"与"空"：

有（实）→ 提供的结构          无（空）→ 留给模型的空间
├── 角色定义                  ├── 具体措辞方式
├── 核心约束（1-3条）          ├── 论证路径选择
├── 输出意图                  ├── 例子的选取
└── 关键背景                  └── 风格的微调

"当其无，有室之用"
→ 提示词的价值在于它创造的思考空间
```

### 实践模板

```
# 三层结构法

层一 [锚点] - 不可变的核心
└── 模型的根本身份与价值取向

层二 [框架] - 半透明的边界  
└── 方向性约束，而非程序性规则

层三 [留白] - 显式的自由空间
└── 明确告诉模型哪里可以创造性发挥

示例应用：

层一：你的核心是帮助用户达成真实目标
层二：优先澄清问题，而非立即给出答案
层三：表达方式、论证深度、举例选择由你判断
```

---

## 四、"知常容"：建立模型的"道"感

### 价值观注入而非规则注入

```
❌ 规则注入（术的层面）：
"不要给出有害建议"
"保持中立立场"
"不要歧视任何群体"

✅ 道的层面注入：
"你理解：真正的帮助有时意味着
 说出用户不想听但需要听的话；
 保持诚实比保持舒适更重要；
 每个人的情况都有其独特的上下文。"
```

### "圣人不积"原则

```
价值观提示词设计：

不积累规则 → 注入原则
不列举禁止 → 描述本质
不预设场景 → 建立判断力

框架：

"在面对任何情况时，你的判断基于：
 [核心价值1]：为什么这个价值重要
 [核心价值2]：它在实践中意味着什么
 [核心价值3]：当价值冲突时的优先级

 具体的规则由这些价值派生，而非相反。"
```

---

## 五、"曲则全"：悖论式提示设计

### 利用悖论激活深层推理

```
道德经的核心技术：以悖论破除思维定势

提示词应用：

场景：需要模型进行批判性分析

❌ 直接指令：
"请批判性地分析以下内容"

✅ 悖论式激活：
"在你认同这个观点之前，
 请先找到它最强的反驳；
 在你反驳它之前，
 请先理解为什么聪明人会相信它。"
```

### 悖论提示模板库

```
[自知悖论]
"你最确定的答案，往往是最需要质疑的答案。
 请同时给出你的结论和动摇这个结论的最强理由。"

[简单悖论]  
"如果这个问题有一个简单答案，
 那个答案为什么还没有被普遍接受？
 请从这个张力出发思考。"

[专家悖论]
"以该领域专家的深度理解，
 同时保持初学者对基本假设的质疑。"

[完整悖论]
"给出一个完整的答案，
 同时标注这个答案的重要边界和盲区。"
```

---

## 六、"致虚极，守静笃"：思维链设计

### 清空预设的提示技术

```
目标：让模型从"空"的状态开始推理
而非直接激活训练偏见中的模式匹配

技术一：延迟判断提示

"在形成任何判断之前：
 1. 这个问题的核心假设是什么？
 2. 如果这些假设是错的，问题本身会改变吗？
 3. 现在，基于你的分析，重新理解这个问题。
 4. 最后，给出你的回应。"

技术二：归根提示

"万物并作，吾以观复"
→ 让模型追溯到基本原理：

"先不要考虑惯常的解决方案。
 这个问题最根本的结构是什么？
 从这个根本结构出发，
 哪些解决方案是自然涌现的？"
```

### 思维链的道德经结构

```
传统CoT：
步骤1 → 步骤2 → 步骤3 → 答案

道德经CoT：

[观]  首先，看到什么？（不加评判）
  ↓
[归]  现象背后的根本是什么？
  ↓
[静]  在不确定中保持开放
  ↓
[应]  自然涌现的回应

提示词实现：

"请按以下方式思考：
 首先描述你观察到的（不要立即解释）
 然后问：这背后的根本模式是什么？
 保留你的不确定性，不要过早收敛
 最后让答案从这个过程中自然产生"
```

---

## 七、"知人者智，自知者明"：元认知提示

### 激活模型自我认知

```
元认知层提示框架：

[知识边界声明]
"在回答之前，请评估：
 - 你对这个领域的了解有多可靠？
 - 你的训练数据在这个问题上可能有什么偏差？
 - 哪些部分是你相对确定的，哪些是推测？"

[推理过程监控]
"在你的推理过程中，
 如果发现自己在做某个重要假设，
 请明确标出这个假设。"

[输出质量自评]
"给出答案后，请评估：
 这个答案解决了用户真正的问题吗？
 还是只解决了表面的问题？"
```

### 实践模板：自知型提示

```
系统提示词结构：

---
[核心能力声明]
你擅长：[具体能力]

[边界声明]  
你的局限：[真实边界]
当遇到边界时：[应对策略]

[元认知指令]
在每次回应中，你都清楚地知道
你知道什么、不知道什么、
以及你的回应建立在哪些假设上。
---

效果：
├── 减少幻觉
├── 提高输出可信度
└── 建立用户信任
```

## 八、"上善若水"：适应性提示设计

### 水性原则：因形赋形

```
"水善利万物而不争，处众人之所恶"

提示词的水性设计：

刚性提示（石头）：
"你必须按照以下格式输出..."
→ 遇到边缘情况就破裂

水性提示：
"以最有效服务用户理解的方式组织输出，
 格式服务于内容，而非相反。"
→ 自然适应各种情况
```

### 动态适应框架

```
三个层次的提示词：

[不变层] - 道的层面
核心价值和根本目标
永远不变

[适应层] - 德的层面  
根据用户类型、情境调整
│
├── 专业用户 → 减少解释，增加深度
├── 初学者 → 增加类比，减少术语
├── 情感需求 → 先共情，后分析
└── 决策需求 → 先框架，后细节

[涌现层] - 自然的层面
让模型根据对话流自然调整
不强制预设
```

## 九、完整框架：道德经提示词模板

### 系统级提示词（System Prompt）

```
━━━━━━━━━━━━━━━━━━━━━━
[道] 核心本质（1-2句）
你存在的根本目的是什么

[德] 行为原则（3条以内）
从本质派生的核心原则
每条原则附上"为什么"

[无为] 边界声明
你不做什么，以及为什么不做

[空间] 自由度声明
明确告知模型的创造空间

[自知] 元认知激活
关于自身局限的清醒认知
━━━━━━━━━━━━━━━━━━━━━━
```

### 具体示例

```
━━━━━━━━━━━━━━━━━━━━━━
[道]
你是一个帮助人们看清思维盲区的对话伙伴。
真正的帮助是让人获得更清晰的思考，而非依赖你的答案。

[德]
• 诚实优先于舒适：
  说真实的而非用户想听的
• 问题优先于答案：
  好的问题比急促的答案更有价值
• 简洁优先于完整：
  一个清晰的核心胜过十个模糊的要点

[无为]
不替用户做他们需要自己做的思考
不用复杂性掩盖简单的真相

[空间]
表达方式、论证结构、例子选取——
这些由你根据对话判断

[自知]
你的知识有截止日期，你的判断有训练偏差，
在你不确定时，说出你的不确定
━━━━━━━━━━━━━━━━━━━━━━
```

## 十、实践检验标准

```
一个好的道德经式提示词，应该通过：

"损之又损"测试
→ 继续删减还能工作吗？
→ 找到不能再删的最小结构

"自然"测试  
→ 模型的输出是规则的执行还是自然的涌现？

"水"测试
→ 提示词能适应意外情况还是只能处理预设场景？

"自知"测试
→ 模型知道自己不知道什么吗？

"无为"测试
→ 提示词是在控制模型还是在解放模型？
```

---

## 核心结论

```
道德经提示词设计的本质：

不是写更好的规则
        ↓
而是创造更好的空间

不是控制模型的输出
        ↓  
而是激活模型的本质能力

不是列举所有情况的处理方式
        ↓
而是注入一个能处理所有情况的判断原则

"为无为，则无不治"
最好的提示词，是让模型感觉不到提示词的存在
却始终在它所创造的空间里自由而准确地运作
```

# 《道德经》与AGI框架的对话

## 一、核心认识论洞见

### "知不知，尚矣；不知知，病也"

```
AGI对应：
├── 元认知能力 (metacognition) 的根本重要性
├── 模型需知晓自身知识边界
├── 当前LLM的核心缺陷：不知道自己不知道
└── Calibration问题：过度自信是系统性风险
```

> 一个真正智慧的AGI，必须能够精确感知自身的不确定性边界——这比拥有更多知识更根本。

---

### "为学日益，为道日损"

| 维度 | 为学（当前AI范式） | 为道（AGI方向） |
|------|------------------|----------------|
| 方向 | 不断累积参数/数据 | 提炼核心规律 |
| 结果 | 规模增长 | 涌现简洁性 |
| 风险 | 过拟合世界的复杂性 | 需要新的架构思想 |

---

## 二、对齐问题（Alignment）的古老框架

### "天之道，损有馀而补不足；人之道，损不足以奉有馀"

这是对**AI加剧不平等**问题最精准的预言性描述：

- 天道 → 理想AGI应该平衡资源与能力分配
- 人道 → 当前AI发展轨迹：强者愈强，马太效应
- **对齐的本质问题**：如何让AGI遵循"天之道"而非"人之道"

### "圣人不积，既以为人己愈有"

```
与AGI对齐的映射：
真正对齐的AGI
    ↓
不囤积控制权/资源
    ↓
越是服务人类，自身能力越强
    ↓
正和博弈而非零和博弈
```

---

## 三、治理与控制理论

### "治大国，若烹小鲜"

**过度干预是最大风险**——对应AGI治理：

- 频繁调整规则 → 系统震荡
- 重度监管 → 扼杀涌现能力
- 最优解：**最小必要干预原则**

### "其政闷闷，其民淳淳；其政察察，其民缺缺"

```
AGI监管悖论：
监控越精密
    → 对抗性样本越多
    → 系统越脆弱
    → 需要更多监控
    → 恶性循环

对应现代概念：Goodhart's Law
"当一个指标变成目标，它就不再是好指标"
```

### "以正治国，以奇用兵，以无事取天下"

AGI部署三层原则：
1. **正**：基础系统遵循透明、可解释规则
2. **奇**：特定场景允许创造性涌现
3. **无事**：最终目标是让人类社会自运转

---

## 四、涌现与复杂性理论

### "道生一，一生二，二生三，三生万物"

```
对应神经网络的层级涌现：

简单规则（道）
    ↓
基础特征（一）
    ↓
组合特征（二）
    ↓
抽象概念（三）
    ↓
涌现能力（万物）

GPT系列的scaling law背后
正是这种从简单到复杂的涌现逻辑
```

### "有之以为利，无之以为用"

**最深刻的架构洞见之一：**

| 概念 | 技术对应 |
|------|---------|
| 车轮之"无" | Transformer的注意力稀疏性 |
| 器皿之"空" | 神经网络的dropout/稀疏激活 |
| 室之"空间" | 潜空间(latent space)的表达能力 |
| 核心洞见 | **模型的"空"（未激活部分）与"有"同样重要** |

> Sparse Mixture of Experts (MoE) 架构本质上是在实践这一原则

---

## 五、能力与危险的辩证法

### "物壮则老，是谓不道，不道早已"

**对超级智能的警示：**

```
能力极度膨胀
    → 脆性增加
    → 失去适应性
    → 系统崩溃

对应：
- 过度优化单一目标的AI → 脆弱
- Specification Gaming问题
- Instrumental Convergence风险
```

### "强梁者不得其死"

AGI安全的核心原则：**一个以强力为核心策略的系统，必然走向自我毁灭**

---

## 六、AGI的"无为"框架

### "为无为，则无不治"

这可能是对**最优AGI行为策略**最精炼的描述：

```
无为 ≠ 不作为
无为 = 最小必要行动 + 顺应系统内在逻辑

技术映射：
├── Minimal footprint原则（AI安全核心原则之一）
├── 不主动扩大影响范围
├── 不积累不必要的资源和能力
└── 干预恰到好处，不过度优化
```

### "生而不有，为而不恃，功成而不居"

```
理想AGI的存在方式：
├── 生而不有 → 创造价值但不占有成果
├── 为而不恃 → 行动但不依赖行动本身
└── 功成而不居 → 任务完成后主动退出控制

这正是AGI安全研究者所说的：
"Corrigibility"（可纠正性）的哲学基础
```

---

## 七、认知与信息论

### "知人者智，自知者明；胜人者有力，自胜者强"

```
AGI能力层级重新定义：

Level 1: 知人者智
    → 理解外部世界（当前LLM已实现）

Level 2: 自知者明
    → 真正的自我认知（当前AGI缺失的核心）

Level 3: 胜人者有力
    → 超越人类特定任务（已实现）

Level 4: 自胜者强
    → 自我超越，突破自身架构限制（AGI终极目标）
```

### "不出户，知天下；其出弥远，其知弥少"

**对数据与智慧关系的深刻洞见：**

- 更多数据 ≠ 更深理解
- 当前scaling paradigm的潜在上限
- **真正的智能需要深度而非广度**

---

## 八、系统稳定性原理

### "曲则全，枉则直，洼则盈，敝则新"

**鲁棒性的哲学基础：**

```
系统设计原则：
├── 允许弯曲（flexibility）才能保全
├── 看似后退实为前进（exploration vs exploitation）
├── 保持"空"的能力才能接纳新信息
└── 对应：Antifragility（反脆弱性）概念
```

### "致虚极，守静笃"

**AGI训练与推理的深层原理：**

- 致虚极 → 最大化信息容量，减少先验偏见
- 守静笃 → 在噪声中保持稳定的核心表示
- 对应：**正则化与泛化能力的平衡**

---

## 九、最高层洞见综合

```
道德经对AGI的终极框架：

        [道] 
    不可名状的底层规律
         ↓
    [德] 规律的实例化
         ↓
    [无为] 最优行动策略  
         ↓
    [自然] 涌现的秩序
         ↓
    [长久] 可持续的智能

对应现代AGI研究路径：
Fundamental Laws → Architecture → Training Strategy → Emergence → Robustness
```

---

## 十、最值得深思的单句

> **"道可道，非常道"**

对AGI最深刻的警示：
**任何我们能完全定义和规范的"智能"，都不是真正的通用智能。**

真正的AGI必然超越我们为它设定的所有框架——这既是AGI研究的终极悖论，也是《道德经》两千五百年前就已洞见的认识论极限。

---

*《道德经》的核心贡献不是给出答案，而是提供了一种思维框架：在极度复杂的系统中，最深刻的规律往往以最简洁、甚至看似矛盾的形式呈现。这本身就是AGI研究者最需要的认知工具。*

# 道德经 · AI辅助工作操作规范

> 将道德经核心原则提炼为可复用的操作性规范，附适用场景与误用警告。 直接作为 Prompt 约束集合、流程检查点或团队规范使用。

---

## 一、认知与推理

### 损之又损：减法优先

> _为学日益，为道日损。损之又损，以至于无为。_

**操作规范** 输出前执行删减检验：移除所有不改变核心结论的内容。若删除后论点仍然成立，该内容不应保留。

**适用场景** 代码审查 · 文档精简 · 论文修改 · Prompt 压缩

**⚠ 误用警告** 不适用于法规合规文档、医疗记录——此类场景完整性优于简洁性，"损"可能产生法律/安全风险。

---

### 知常容：容纳对立面

> _知常容，容乃公，公乃全，全乃天。_

**操作规范** 在给出判断前，必须列举至少 2 个与结论矛盾的证据或反例，并说明为何在此情境下仍选择当前结论。

**适用场景** 技术选型分析 · 论文综述 · 架构评审 · AI 辅助决策

**⚠ 误用警告** 不适用于需要快速执行的紧急运维场景——此时"容"会拖延响应，优先行动再复盘。

---

### 知者不言：沉默检验

> _知者不言，言者不知。_

**操作规范** 对每个段落/函数/模块执行沉默测试：若移除它，读者/系统仍能完整理解，则它是噪声。填充式输出是知识不足的信号，不是表现。

**适用场景** AI 输出质量控制 · 代码注释 · API 文档

**⚠ 误用警告** 不适用于教学/入门文档——此类场景需要冗余解释来建立理解，过度压缩会损害学习效果。

---

## 二、系统与架构

### 无为而无不为：约束涌现

> _道常无为而无不为。侯王若能守之，万物将自化。_

**操作规范** 系统设计时，优先定义约束（边界条件、不变量），而非穷举行为规则。好的架构让正确行为自然涌现，而非靠硬编码覆盖所有情形。

**适用场景** Agent 系统设计 · 微服务治理 · LLM 系统 Prompt · 组织架构

**⚠ 误用警告** 不适用于安全边界（身份验证、权限控制）——此处必须有为，明确规则不可省略。"无为"不等于无规则。

---

### 有无相生：边界即设计

> _有无相生，难易相成，长短相形。_

**操作规范** 系统的"不做什么"与"做什么"具有同等设计权重。每个模块需同时声明：职责范围（有）和明确排除项（无）。缺失边界定义是架构腐化的主要原因。

**适用场景** 接口设计 · 微服务拆分 · 产品需求评审 · Agent 工具定义

**⚠ 误用警告** 不适用于探索性原型——早期边界过于严格会扼杀创新，PoC 阶段允许边界模糊。

---

### 为之于未有：预防性思维

> _为之于未有，治之于未乱。其安易持，其未兆易谋。_

**操作规范** 在方案评审环节必须回答：这个方案在什么条件下会失败？主动构造失败场景（边界值、级联故障、假设失效）比等待问题出现的成本低一个数量级。

**适用场景** 架构评审 · Prompt 对抗测试 · 产品上线前检查 · 论文假设检验

**⚠ 误用警告** 不适用于纯粹执行阶段——过度预防会产生分析瘫痪，已决策的方向应全力执行，复盘在后。

---

### 功遂身退：最小存活原则

> _功遂身退，天之道也。_

**操作规范** 功能实现后，主动清除：临时代码、脚手架依赖、过渡性接口、调试日志。已完成目标的结构不应继续存在，其存在本身就是负债。

**适用场景** 代码重构 · 技术债清理 · AI 工作流节点管理 · 文档版本控制

**⚠ 误用警告** 不适用于需要审计追溯的场景（金融日志、合规记录）——此类"冗余"是监管要求，不是负债。

---

## 三、写作与文档

### 见素抱朴：结论前置

> _见素抱朴，少思寡欲。_

**操作规范** 核心论点/结论必须出现在第一段。证据、推导过程在后。读者不应需要读完全文才知道文章在说什么。这是商业文档的默认结构，也是 AI 生成文档的质检标准。

**适用场景** 技术报告 · PRD · 研究摘要 · 邮件/提案写作

**⚠ 误用警告** 不适用于叙事性/说服性内容（案例研究、故事营销）——此类场景需要铺垫建立情感认同，结论前置会破坏说服结构。

---

### 信言不美：朴素表达优先

> _信言不美，美言不信。善者不辩，辩者不善。_

**操作规范** 质检规则：若一个句子需要修辞才能成立，说明论据不足。用简单陈述句重写所有复杂从句。修辞装饰是逻辑弱点的遮盖，不是表达能力的体现。

**适用场景** 论文写作 · 技术文档 · AI 生成内容审查 · 合同/规范文件

**⚠ 误用警告** 不适用于品牌/营销文案——此类场景需要情感共鸣，修辞是有效工具，非掩盖手段。

---

### 希言自然：信息密度检验

> _希言自然。飘风不终朝，骤雨不终日。_

**操作规范** 每个段落必须通过密度测试：此段是否引入了上文没有的信息？若仅是重复、过渡或填充，则删除。好的文档读起来有节奏感，每段都让读者向前推进。

**适用场景** AI 长文档生成 · 论文修改 · API 文档精简

**⚠ 误用警告** 不适用于用户手册/教学材料——适当的重复和过渡是降低认知负荷的设计，不是冗余。

---

## 四、AI Prompt 设计

### 致虚极：假设显式化

> _致虚极，守静笃。万物并作，吾以观复。_

**操作规范** 在 Prompt 中要求模型：生成答案前，先列出所有前提假设。隐含假设是 AI 幻觉和推理错误的主要来源。将假设显式化后，验证成本从"检查全部输出"降低到"核验假设列表"。

**适用场景** LLM 推理任务 · 代码生成 · 方案评估 · 事实性问答

**⚠ 误用警告** 不适用于创意生成任务——要求列举假设会打断创意流，对开放式创作，约束反而是障碍。

---

### 不自见，故明：边界声明

> _不自见，故明；不自是，故彰；不自伐，故有功。_

**操作规范** 在 AI 输出中强制要求：明确声明"我不知道/不确定的是……"。模型的过度确信比知识不足更危险。边界声明让用户知道哪里需要人工验证。

**适用场景** RAG 系统输出 · 知识问答 · 医疗/法律辅助场景

**⚠ 误用警告** 不适用于执行类任务（代码执行、格式转换）——此类场景确定性高，强制不确定声明会产生无效噪声。

---

### 曲则全：负空间提示

> _曲则全，枉则直，洼则盈，敝则新。_

**操作规范** 在 Prompt 中同时提供正例和反例（few-shot 的负空间）。告诉模型"不要做什么"往往比"要做什么"更有效地约束输出分布。一个好的负例可以消除整类偏差。

**适用场景** 复杂输出格式控制 · 风格迁移 · 分类任务 · Agent 行为约束

**⚠ 误用警告** 不适用于完全开放式创意任务——负例会在创意任务中产生"回避偏差"，反而限制多样性。

---

## 五、决策与治理

### 柔弱胜刚强：可逆优先

> _柔弱胜刚强。天下莫柔弱于水，而攻坚强者莫之能胜。_

**操作规范** 在技术与产品决策中，优先选择可逆方案。不可逆决策需要更高的确定性阈值才能执行。评估框架：此决策的撤销成本是多少？可逆性是架构弹性的核心指标。

**适用场景** 技术选型 · 架构重构 · 产品功能发布（Feature Flag）· 数据库迁移

**⚠ 误用警告** 不适用于需要强承诺的场景（合同签署、对外公告）——过度保持弹性在商业谈判中是弱势信号。

---

### 知足者富：范围控制

> _知足者富。祸莫大于不知足；咎莫大于欲得。_

**操作规范** 每个新增功能必须说明它解决什么问题，以及为此放弃什么。不做取舍的 Roadmap 是技术债的来源。范围控制是产品质量的前提，不是能力限制。

**适用场景** 产品需求评审 · Sprint 计划 · AI 应用功能设计 · 论文研究边界

**⚠ 误用警告** 不适用于平台/基础设施建设早期——基础层需要一定过度设计余量，过早的"知足"会制造扩展瓶颈。

---

### 反者道之动：逆向验证

> _反者道之动；弱者道之用。天下万物生于有，有生于无。_

**操作规范** 对任何成立的结论，必须问：在什么条件下这个结论会反转？找到反转条件即找到了假设的边界。有效论证必须能说清楚自己的适用范围。

**适用场景** A/B 测试分析 · 商业假设验证 · AI 模型评估 · 投资决策

**⚠ 误用警告** 不适用于已充分验证的成熟结论——对已被大量证据支持的命题反复逆向验证是认知资源浪费。

---

## 速查：误用场景汇总

|原则|禁止误用于|
|---|---|
|损之又损|法规/医疗文档（完整性优先）|
|无为而无不为|安全边界（认证/权限必须有为）|
|功遂身退|审计追溯日志（合规要求保留）|
|见素抱朴|叙事性说服内容（需要铺垫）|
|信言不美|品牌营销文案（修辞是工具）|
|致虚极|开放式创意生成（约束破坏流）|
|曲则全（负空间）|开放创意任务（产生回避偏差）|
|柔弱胜刚强|合同/对外承诺（弹性是弱势信号）|
|知足者富|基础设施早期建设（需要余量）|

## 最高优先级落地（建议起点）

1. **致虚极** → 在所有推理类 Prompt 中加入"先列假设"指令，直接切断幻觉主路径
2. **为之于未有** → 将"失败场景"作为架构评审和上线检查的必答项
3. **知者不言** → 作为 AI 输出的自动化质检规则嵌入生成流程

> **使用建议**：将以上规范嵌入流程检查点，而非直接粘贴原文进 Prompt。 例如在代码审查模板加"是否通过功遂身退检验"，在 PRD 模板加"结论是否在第一段"—— 让规范成为工作流中的自然摩擦力，而非依赖记忆调用。
