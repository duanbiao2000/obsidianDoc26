这页介绍了**动态规划（Dynamic Programming, DP）**的基本思想：把复杂问题拆成可复用的小问题，保存小问题的答案，从而避免重复计算。它尤其适用于同时满足“重叠子问题”和“最优子结构”的问题。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 核心条件

- **重叠子问题**：同一个子问题会在求解过程中被反复遇到，因此值得缓存结果。
    
- **最优子结构**：原问题的最优解可以由其子问题的最优解组合得到。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]
    

## 斐波那契例子

斐波那契数满足：

F(n)=F(n−1)+F(n−2)F(n)=F(n-1)+F(n-2)F(n)=F(n−1)+F(n−2)

要计算 F(n)F(n)F(n)，需要先计算 F(n−1)F(n-1)F(n−1) 和 F(n−2)F(n-2)F(n−2)；但这两个过程又会重复计算如 F(4)F(4)F(4) 等更小问题。DP 将每个 F(k)F(k)F(k) 的结果保存下来，只计算一次。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 为什么有用

普通递归求斐波那契会产生大量重复调用，时间复杂度可达指数级；采用 DP 复用已算结果后，时间复杂度可降至线性级别。DP 的价值不只是“拆分问题”，更关键是**记录并复用重叠子问题的答案**。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 与相似思路的区别

- **贪心算法**：通常也有最优子结构，但不一定存在重叠子问题。
    
- **分治算法**：也会递归拆分，但子问题通常彼此独立、不重叠。
    
- **动态规划**：既拆分，又缓存重复子问题的解。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]
    

下一节会讲 DP 的两种实现方向：**自顶向下（记忆化搜索）**与**自底向上（递推/填表）**。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]


动态规划主要有两种实现方式：**自底向上（bottom-up / tabulation）** 与 **自顶向下（top-down / memoization）**。两者本质上都通过保存子问题答案来消除重复计算，但计算方向和代码形式不同。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 自底向上

自底向上使用**迭代**：从最简单、已知的基础状态开始，按明确顺序逐步推导到目标状态。以斐波那契数列为例，先设 F(0)=0F(0)=0F(0)=0、F(1)=1F(1)=1F(1)=1，再依次计算 F(2),F(3),…,F(n)F(2), F(3), \ldots, F(n)F(2),F(3),…,F(n)。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

python

`dp = [0] * (n + 1) dp[0], dp[1] = 0, 1 for i in range(2, n + 1):     dp[i] = dp[i - 1] + dp[i - 2]`

优点是通常运行更快，因为循环没有递归调用的额外开销；难点是你必须提前想清楚状态之间的依赖顺序。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 自顶向下

自顶向下使用**递归 + 记忆化**：从目标问题 F(n)F(n)F(n) 出发，递归地请求它依赖的更小问题；第一次计算后，将结果存入缓存，之后遇到同一状态就直接返回缓存值。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

python

`from functools import cache @cache def f(i):     if i <= 1:        return i    return f(i - 1) + f(i - 2)`

优点是写法往往更接近递推公式、更加直观；缓存避免了普通递归中对同一状态（如 F(2)F(2)F(2)）反复计算的问题。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 如何选择

|情况|更适合的实现|
|---|---|
|想快速把递推关系写成代码|自顶向下：递归 + 缓存。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]|
|状态转移顺序清晰，追求较低常数开销|自底向上：迭代填表。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]|
|只会访问少量状态|常倾向自顶向下，因为它按需求值。|
|所有状态大概率都要计算，或需空间优化|常倾向自底向上。|

记忆口诀：**Top-down 是“从问题出发，递归求解并缓存”；Bottom-up 是“从基础出发，循环填表到答案”。**[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

判断一道题是否应考虑动态规划，重点看两类信号：题目在求“最优值/方案数/可达性”，并且当前选择会限制或改变后续选择。此时单步看起来最优的贪心策略未必能保证全局最优。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 识别信号

以下提问方式常是 DP 的候选信号，但还需继续验证状态之间是否相互影响：[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

- 最小成本、最大收益
    
- 最长或最短长度
    
- 完成目标的方案数
    
- 是否能够到达某个状态或位置
    

## DP 与贪心

如果每一步的选择不会损害未来可选方案，贪心可能成立；但若“现在拿什么/不拿什么”会改变未来能做什么，就应考虑 DP，系统比较不同历史决策的结果。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

实用检验法：**先假设贪心可行，再尝试构造反例。**如果能找到一个例子，使得局部最优选择导致错过整体更优解，说明贪心不可靠，DP 很可能适用。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]

## 两个例子

- **打家劫舍**：相邻房屋不能同时选。面对 `[2, 7, 9, 3, 1]`，若贪心地先选 7，会失去选择 9 的机会；最优方案其实是选 2、9、1，总额为 12。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]
    
- **最长递增子序列**：在 `[1, 2, 6, 3, 5]` 中，选 6 会阻止后续选 3 和 5；最佳子序列是 `[1, 2, 3, 5]`，长度为 4。因此不能只依据当前元素是否“看起来更大”做决定。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]
    

## 面试判断框架

看到“最大/最小/最长/方案数/能否到达”时，先问：

1. 能否定义一个较小规模的子问题？
    
2. 子问题是否会被反复使用？
    
3. 当前决策会不会影响后面的可选决策？
    
4. 能否构造一个反例，推翻简单贪心？
    

若答案多为“是”，就尝试设计 DP 状态与状态转移；页面也强调，这些只是高频经验信号，DP 的适用范围本身很广。[[leetcode](https://leetcode.com/explore/learn/card/dynamic-programming/630/an-introduction-to-dynamic-programming/4034/)]
