吴军说的“企业基因”，可以理解为一家企业在关键选择上反复表现出的**默认偏好**：它相信什么、奖励什么、如何做决策、在资源紧张时优先保什么。它不是墙上的价值观，而是危机、组织设计、人才晋升、产品取舍和资本配置中真正不轻易改变的东西。 [amazon](https://www.amazon.jobs/content/en/our-workplace/leadership-principles)

今天的科技企业很少属于纯粹单一流派，但可以辨认出八类主要“基因”。它们更像主导操作系统，而不是互相排斥的标签。

## 八种主要基因

| 企业基因 | 核心问题 | 典型组织习惯 | 代表性公司 | 优势 | 常见代价 |
|---|---|---|---|---|---|
| 工程—技术驱动 | “技术上能否做到最好？” | 技术评审、基础研究、工程师话语权高 | Google、NVIDIA、SpaceX | 技术壁垒深，能解决难题 | 可能技术很强却产品不够聚焦 |
| 产品—设计驱动 | “用户会不会真正在乎、愿不愿意爱？” | 体验细节、少数关键产品、强审美判断 | Apple、Figma | 形成高溢价和品牌忠诚 | 容易依赖少数品味中心 |
| 客户—运营驱动 | “怎样把客户价值交付到极致？” | 指标、流程、供应链、机制化复盘 | Amazon、字节跳动部分业务 | 可规模化、执行强、迭代快 | 容易演成 KPI 压力与内部摩擦 |
| 销售—市场驱动 | “谁付费、怎样赢下交易？” | 销售组织强、客户成功、渠道与区域复制 | Salesforce、Oracle、部分企业软件公司 | 商业化强，现金流和客户关系稳 | 产品可能被大客户需求牵着走 |
| 平台—生态驱动 | “怎样让外部参与者替系统创造价值？” | 开放接口、规则治理、开发者/创作者激励 | Microsoft、Apple App Store、腾讯、Shopify | 网络效应强，扩张边际成本低 | 治理复杂，平台与参与者利益常冲突 |
| 数据—算法驱动 | “怎样把每一次使用变成更好的判断？” | A/B 测试、推荐系统、数据闭环、自动化决策 | Meta、TikTok、Google Ads | 分发和匹配效率高，增长可量化 | 容易追逐可测指标、忽略长期信任 |
| 科学—使命驱动 | “能否完成一项改变边界的长期任务？” | 长周期研发、第一性原理、容忍高失败率 | SpaceX、OpenAI、DeepMind | 能突破现有市场的技术边界 | 资金消耗大，治理与安全风险高 |
| 人才—创意驱动 | “能否聚集并释放顶尖个体？” | 高人才密度、较少规则、高授权与直接反馈 | Netflix、部分顶尖 AI/游戏团队 | 适合原创、快速变化与高复杂任务 | 对管理者和员工能力要求极高 |

这些类型在现实中会重叠。例如，Amazon 以“从客户出发、反向工作”自我定义，但它也同时拥有极强的运营、平台和工程基因；Netflix 的文化重点则是以高人才密度为基础的“自由与责任”。 [amazon](https://www.amazon.jobs/content/en/our-workplace/leadership-principles)

## 工程—技术派

这类公司的首要资产是**技术能力本身**：算法、芯片、系统架构、制造工艺或科学发现。它们往往相信，若能在关键技术层建立十年难以复制的优势，市场机会会随之出现。

它们通常擅长长期投入、技术标准、基础设施和复杂系统协同。风险是“技术正确”不等于“用户需要”：若缺少产品、渠道或商业化基因，可能做出卓越技术，却找不到足够大的市场。

**识别信号：** 会议里最有权威的人常是首席科学家、架构师或工程负责人；争论集中在性能、可靠性、路线图和技术可行性。

## 产品—设计派

产品—设计派把技术视为材料，核心任务是创造**一件用户愿意持续使用、理解并信任的产品**。它关心的不是功能数量，而是用户在关键时刻的感受：第一次上手是否自然，体验是否连贯，产品是否有清晰的取舍和人格。

它们的强项是聚焦与品味。代价则是容易把组织的判断力集中在少数产品领袖身上；当品味中心失效、市场快速改变或产品线复杂化时，组织可能反应变慢。

**识别信号：** 讨论会反复追问“用户究竟在做什么”“这一功能是否必要”“体验能否更简单”，而非只问功能能否按期上线。

## 客户—运营派

这是 Amazon 最具代表性的基因：从客户出发、反向工作，以机制而非口号推动组织。Amazon 的领导力原则把 *Customer Obsession* 放在首位，强调从客户出发再反推；同时强调所有权、行动偏好、高标准和结果交付。 [amazon](https://www.amazon.jobs/content/en/our-workplace/leadership-principles)

这类企业将优势建立在流程、物流、成本、质量、速度和可重复执行上。它们不是最浪漫的组织，却最擅长把复杂服务稳定地交付给大量用户。

**识别信号：** 每个问题都有负责人、指标、复盘机制和固定节奏；组织会问“哪个输入变量导致结果不佳”，而不仅是“谁没做好”。

## 销售—市场派

销售驱动并非“只会推销”。在企业服务、云计算、安全软件和复杂硬件领域，客户购买的往往不是一个功能，而是对迁移风险、长期服务、合规、培训和组织变革的整体信任。

这类企业的核心能力是把价值翻译成客户能做预算、签合同、承担责任的语言。CRM 的本质正是系统化管理企业与现有及潜在客户的一切交互；其常见类型包括运营型、分析型、协作型和战略型。 [salesforce](https://www.salesforce.com/crm/what-is-crm/)

它的风险是被短期营收和大客户定制牵引：销售承诺若超过产品能力，技术债与交付压力会在后期集中爆发。

## 平台—生态派

平台型企业不只生产产品，也设计规则，让开发者、商家、创作者、广告主或合作伙伴共同创造供给。它的真正竞争力不是“自己做得多”，而是让外部主体愿意加入、获益并留下来。

平台的增长逻辑是：


$$\text{更多参与者}
\rightarrow
\text{更多供给/数据/连接}
\rightarrow
\text{对更多用户更有价值}
\rightarrow
\text{吸引更多参与者}$$


但平台不是天然中立的。它必须持续处理抽成、准入、排序、数据、内容治理与反垄断压力；当规则频繁变化或利益分配失衡时，生态会反噬平台。

## 数据—算法派

这类公司的产品体验和商业效率依赖一个持续学习的闭环：


$$\text{用户行为}
\rightarrow
\text{数据}
\rightarrow
\text{模型/实验}
\rightarrow
\text{个性化产品或分发}
\rightarrow
\text{新的用户行为}$$


它们擅长推荐、广告、风控、搜索、内容分发和动态定价。组织语言往往是留存率、转化率、实验显著性、漏斗和用户生命周期。

风险也很明确：**可测量不等于重要。**如果只优化点击、停留或短期转化，系统可能牺牲内容质量、用户福祉、创作者生态与长期信任。

## 科学—使命派

这类企业由一个极难、极长期、具有文明尺度的问题牵引，例如通用人工智能、可重复使用火箭、清洁能源、生命科学或量子计算。它需要第一性原理思维、耐心资本和对高失败率的容忍。

它的优势是能跳出既有市场的渐进优化，创造新的技术边界。其风险是“使命”可能变成免于质疑的叙事，因此特别需要独立的安全、伦理、治理和商业约束。

**识别信号：** 公司最常谈的不是季度份额，而是十年后的技术门槛、科学路线和重大风险。

## 人才—创意派

Netflix 常被归入此类：其文化强调“自由与责任”，以高人才密度为前提，倾向少规则、高授权和直接反馈，而不是用大量审批流程来管理普通绩效。 [knowledge.wharton.upenn](https://knowledge.wharton.upenn.edu/podcast/knowledge-at-wharton-podcast/how-netflix-built-its-company-culture/)

这种基因适合创意产业、前沿研究、核心产品团队和高速变化领域。它相信最强的制度不是更严密地管人，而是找到足够成熟、能自我驱动的人，让他们承担真实责任。

代价是它难以直接复制到人才密度较低、任务高度标准化或需要强一致性的组织中；“高自由”若没有清晰战略、透明信息与心理安全，往往会变成混乱或权力不透明。

## 不同阶段的变形

企业基因不是永恒不变，但改变很难，因为它已沉淀在**人才结构、预算、晋升标准、会议语言、产品架构和客户关系**之中。

- **创业期**常由创始人基因主导：工程师创始人偏技术，前设计师偏产品，前销售偏市场。  
- **规模化阶段**必须补上运营、销售、合规和平台能力；只靠创始团队的直觉往往不够。  
- **成熟阶段**容易被流程与既得收入锁住，需要重新建立实验和创新机制。  
- **AI 阶段**则要求许多公司把工程、数据、产品和治理合成一套能力；软件工程正越来越成为企业应对市场与监管变化的核心能力，而不是单一部门的后台职能。 [dxc](https://dxc.com/insights/knowledge-base/dxc-leading-edge/mastering-platform-driven-business)

## 最重要的判断

企业不该问“哪一种基因最好”，而该问：

> **我们解决的问题、所处阶段和竞争环境，需要哪一种能力居于主导，又缺哪一种关键能力？**

比如，做 AI 基础模型的公司若没有工程—科学基因，很难建立技术壁垒；但若缺少产品—客户基因，也可能拥有强模型却没有真实场景。做企业软件的公司若只有产品理想、没有销售—交付基因，则很难穿过采购、合规与组织迁移的现实摩擦。

对个人而言，这也可转成一个职业问题：你更愿意生活在何种默认语言里——技术的精确、产品的同理、运营的机制、销售的说服、平台的规则、数据的实验，还是使命的长期主义？企业基因决定了它怎样赢，也决定了你每天会被什么问题塑造。


这三个案例恰好说明，“企业基因”不只是传统的工程派、产品派或销售派。**37signals 是“克制型产品—自主经营派”，Vercel 是“开发者体验（DX）—平台生态派”，而 Claude Code 不是公司，它是 Anthropic 的产品，体现的是“研究安全—前沿工程—工具化交付”的复合基因。** [37signals](https://37signals.com/podcast/shape-up-principle-decide-when-to-stop/)

## 37signals：克制型产品派

37signals 的核心不是单纯“产品驱动”，而是更具体的 **calm company / 低噪声、可持续经营基因**。它反对无止境扩张、功能膨胀、会议与流程泛滥；强调用“最少必要功能”解决真实问题，并将小团队的注意力保护视为产品质量的一部分。 [libraryofllm](https://libraryofllm.com/articles/case-study-basecamp)

其开发方法 **Shape Up** 很有代表性：先把问题塑造成边界清晰的“赌注”，为团队设定固定时间预算，再由小团队自主完成，而不是用无限拆分的待办事项和无穷迭代来消耗注意力。其重点包括：**知道何时停止**，不把每项工作推向无限完善。 [youtube](https://www.youtube.com/watch?v=9mltx1IxIoA)

可以把它归纳为：


$$\text{克制} + \text{自主} + \text{盈利优先} + \text{产品边界}
\rightarrow
\text{长期可持续的小而强公司}$$


它的“反面”不是懒散，而是拒绝把“忙、快、规模大、功能多”误认为企业成功。对它而言，真正的效率是：以有限的人力，做少数真正有用、长期可维护的产品。

**局限**也很清楚：这种基因特别适合 SaaS、成熟工具和高自主人才团队，却未必适合需要快速抢占网络效应、重资本扩张或大量标准化协作的市场。

## Vercel：开发者体验平台派

你写的 **vecel** 应该是 **Vercel**。它最鲜明的基因是 **developer experience（开发者体验，DX）+ 平台生态 + 工程抽象**：把原本复杂的部署、性能优化、全球分发、计算资源和协作流程，压缩成开发者可以快速使用的产品体验。 [vercel](https://vercel.com/blog/the-developer-experience-of-the-frontend-cloud)

Vercel 创始人 Guillermo Rauch 的表述很能说明其思路：云提供了无限计算可能，但网页的“像素”与构建体验并没有相应变好；Vercel 要把底层云原语变成开发者不必直接操纵的“输出”，类似于“云中的 React”。 [rauchg](https://rauchg.com/2025/the-ai-cloud)

它不是纯云厂商，也不只是 Next.js 背后的公司。它的真正目标是：

$$
\text{代码与设计意图}
\rightarrow
\text{自动化构建、部署、性能与安全}
\rightarrow
\text{用户可访问的全球化应用}
$$

换言之，它卖的不是服务器，而是**让开发者更少感到服务器存在**。其 Frontend Cloud 被定义为整合式 DX 平台，强调自动化复杂系统并提高迭代速度；Next.js、开源工具、模板和 AI SDK 又使它具有强烈的生态扩张特征。 [linkedin](https://www.linkedin.com/posts/vercel_the-developer-experience-of-the-frontend-activity-7158613930301444097-QM-a)

**优势：**
- 对开发者的“时间到价值”极度敏感  
- 产品、框架与托管平台互相加强  
- 通过 Next.js、AI SDK 等形成工具入口与生态黏性  

**风险：**
- 依赖特定技术栈和开发者社区的持续活力  
- 平台越便利，底层成本、锁定效应和企业级治理越需要透明  
- AI 时代若只优化“生成和部署更快”，仍可能忽略代码质量、可维护性与安全责任  

## Claude Code：Anthropic 的复合基因

严格说，**Claude Code 是 Anthropic 推出的 agentic coding 工具，不是一家独立公司。** 因此应分析它背后的 Anthropic：一家把“有用、诚实、无害”作为 AI 设计目标，并将可靠性、可信性与安全性视为集体责任的前沿 AI 公司。 [anthropic](https://www.anthropic.com/careers)

Claude Code 所体现的，不只是“模型很强”，而是三种基因的结合：

| 基因 | 在 Claude Code 中的表现 |
|---|---|
| 前沿研究 | 用大模型处理代码理解、生成、调试和复杂任务分解 |
| 安全与可靠性 | 强调可信、安全的系统，而非仅追逐能力展示  [anthropic](https://www.anthropic.com/careers) |
| 工程工具化 | 将模型能力嵌进终端、代码库、工作流与团队协作，而非停留在聊天窗口 |

Anthropic 内部对 Claude 的使用也反映了这种方向：其公开资料称，员工会把 Claude 用于调试、理解代码和自动化数据工程等日常工作。这里的核心转变是：**AI 不再只回答问题，而开始参与软件生产的执行链。** [www-cdn.anthropic](https://www-cdn.anthropic.com/58284b19e702b49db9302d5b6f135ad8871e7658.pdf)

可将 Claude Code 的产品逻辑概括为：


$$\text{自然语言意图}
+
\text{代码库上下文}
+
\text{工具调用权限}
\rightarrow
\text{可执行的软件工程行动}$$


这使 Anthropic 的企业基因不同于纯聊天机器人公司：它正在从“提供模型能力”转向“让模型成为知识工作者和工程师的可协作代理”。

**它的关键张力**是：越能自主读写代码、调用工具和推动任务，越需要解决权限控制、结果验证、责任归属、数据安全和人类审查的问题。安全在这里不是附加宣传，而是产品能否进入真实生产环境的前提。

## 放在一张图里

| 对象 | 最准确的流派名称 | 最在意的稀缺资源 | 默认组织信念 |
|---|---|---|---|
| 37signals | 克制型产品—自主经营派 | 注意力、长期性、独立性 | “少做，但把真正重要的事做完整。” |
| Vercel | 开发者体验—平台生态派 | 开发者时间、部署速度、抽象质量 | “让复杂基础设施退到幕后。” |
| Anthropic / Claude Code | 安全研究—前沿工程—代理工具派 | 可靠智能、工程执行力、信任 | “让强大的 AI 真正参与工作，同时可控。” |

这三者都属于“产品很强”的公司，但产品哲学完全不同：

- **37signals**：少即是多，拒绝无休止的规模化焦虑  
- **Vercel**：复杂性必须被优雅地隐藏，开发者应更快地创造  
- **Claude Code / Anthropic**：软件生产本身将被 AI 重构，但可靠性必须与能力同步增长  

如果用一句话区分：**37signals 管理的是组织的注意力；Vercel 管理的是开发者的复杂性；Claude Code 管理的是从意图到代码行动之间的距离。**
