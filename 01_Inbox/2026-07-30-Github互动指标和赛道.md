Trendshift Signal 的 **engagement spike** 目前主要看 GitHub 仓库内部的五类活动变化：**Stars、Forks、已合并 PR、Issues、新关闭 Issues**。它不是简单按总量排序，而是寻找某个时间窗口内某项指标增长显著、且与其他指标表现出现差异的仓库。 [api.trendshift](https://api.trendshift.io/docs)

## 主要互动指标

| 指标 | 它代表什么 | 常见解读 |
|---|---|---|
| **Stars** | 开发者收藏、关注或认可项目 | 突增通常意味着项目被传播、登上热门榜、发布新版本或被社区推荐。  [api.trendshift](https://api.trendshift.io/docs) |
| **Forks** | 用户复制仓库以修改、部署或二次开发 | 相比 Star，更接近“我准备动手用/改它”；Fork 激增可能代表开发者实际采用意愿上升。  [api.trendshift](https://api.trendshift.io/docs) |
| **Merged PRs** | 被维护者接受并合并的拉取请求 | 表示外部贡献与项目协作活跃；对基础设施、框架、开发工具类项目尤其有参考价值。  [api.trendshift](https://api.trendshift.io/docs) |
| **Issues** | 新建问题、需求、讨论或使用反馈 | 增长可能表示用户涌入、需求增加，也可能意味着新版本引入问题，因此不能单独视为正向信号。  [api.trendshift](https://api.trendshift.io/docs) |
| **Closed issues** | 被关闭/解决的 Issues 数量 | 通常反映维护响应和问题处理吞吐；若与新 Issues 同时增长，可能说明项目正在快速扩张但维护仍跟得上。  [api.trendshift](https://api.trendshift.io/docs) |

## 如何理解“分化”

“分化”并非某个官方统一的综合评分，而是同一项目的不同指标呈现不一样的变化形态。Signal 的定位是帮你发现这些活动计数在时间窗口内有明显变化的仓库。 [trendshift](https://trendshift.io/signal)

几个有用的判断模式：

- **Stars 大涨，Fork 很少，PR/Issue 也少**：大概率是“被看见/被讨论”，比如产品发布、社交媒体传播或一次 Demo 出圈；还不能说明真正采用。
- **Fork 与 Stars 同时上涨**：通常比单纯 Star 更值得研究，意味着更多开发者正尝试部署、修改或基于它开发。
- **Issues 和 Merged PR 同时上涨**：社区与维护者都很活跃，常见于快速成长期的开源基础项目。
- **Issues 大涨，但 Closed issues 跟不上**：用户增长可能快于维护能力，也可能意味着版本稳定性、文档或支持存在压力。
- **Closed issues 大涨，Stars 平稳**：可能是维护团队在集中清理积压、发布稳定版本，属于“健康度改善”而不一定是市场热度上升。

## “赛道”从哪里来

Signal API 公开说明的三类能力是：spike、Trendshift 榜单、GitHub Trending 历史快照；页面**没有说明 spike endpoint 自带固定的赛道/分类字段或赛道榜单**。 [trendshift](https://trendshift.io/)

因此，“赛道”通常要由你自己对仓库 metadata 进行二次分类，例如基于 GitHub topics、README、语言、依赖关系或 LLM 标签。Trendshift 网页的 topic 页面已覆盖如 **AI agent、AI coding assistant、AI skills、AI voice、AI workflow、MCP、Local LLM、RAG、Self-hosted、Web scraping、Video editing** 等主题，适合作为初始分类词典。 [trendshift](https://trendshift.io/topics/ai-coding)

## 建议关注的赛道

对你的工作流，建议优先建立这些雷达：

- **AI Coding / Agent 工具链**：AI agent、AI coding assistant、AI workflow、AI skills、MCP、Agent memory、terminal multiplexing。
- **本地 AI 基础设施**：Local LLM、模型网关/Proxy、推理服务、GPU/部署、Sandbox、安全权限控制。
- **语音与教育内容生产**：AI voice、TTS、STT、实时语音 Agent、视频编辑、字幕和音视频自动化。
- **知识与研究自动化**：RAG、搜索、网页抓取、文档处理、个人知识库、Research Agent。
- **可自托管生产力工具**：Self-hosted、身份认证、备份、监控、数据库、工作流自动化。

## 一个筛选原则

若你要把它做成每日自动报告，不要只按 Star spike 排序。可优先挑选满足以下任一条件的项目：

- Stars 和 Forks 同时突增；
- Issues 上升但 Closed issues 的比例没有恶化；
- Merged PRs 持续上升；
- 同一赛道中连续多天/多周出现在 Trendshift 榜单或 GitHub Trending 快照。

这会比“某项目一夜多了很多 Star”更接近可持续的开发者采用和社区活跃度判断。Trendshift 也提供日、周、月、年榜及 GitHub Trending 的按日历史快照，正好可用于对 spike 做后续验证。 [trendshift](https://trendshift.io/)
