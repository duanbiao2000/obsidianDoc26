“减法审查（subtraction review）”只审查能否删掉、收紧或简化不必要的内容；它不是完整的工程质量审查。因此，正确性、安全性、性能仍然必须审，只是应由正常的 code review / 测试 / 安全审查流程负责，而不能因为追求“极简”就被遗漏。该仓库本身把风格规则定位为输出塑形，而不是替代系统提示、工具要求或安全约束。

## 术语逐个解释

| 术语 | 在这里的含义 | 典型问题 |
|---|---|---|
| **Correctness（正确性）** | 代码是否按需求正确运行；边界条件、错误处理、数据一致性、测试结果是否正确 | 条件判断写反、漏处理 `null`、重构后功能失效 |
| **Security（安全性）** | 是否引入可被利用的风险，或暴露敏感数据与权限边界 | SQL 注入、XSS、路径遍历、密钥提交进仓库、鉴权绕过 |
| **Performance（性能）** | 时间、内存、I/O、网络、数据库等资源使用是否在可接受范围 | N+1 查询、大数组重复复制、热路径 \(O(n^2)\)、不必要的 API 调用 |
| **Code review（代码审查）** | 面向工程质量的完整检查流程；通常覆盖需求、设计、正确性、测试、可维护性、安全与性能 | “这个改动能不能合并？” |
| **Subtraction review（减法审查）** | 专项、受限的审查：寻找可以删除、合并、缩短、延后或不展示的内容，以降低复杂度和认知负担 | “这个抽象、配置、分支、输出段落真的必要吗？” |
| **Scope（范围）** | 某次审查被授权检查什么、不检查什么的边界 | “本轮只评估简化空间，不给安全结论” |
| **极简（minimalism）** | 用更少的结构、文字、分支与选择完成同样目标；不是“越少越好” | 删除必要验证或错误处理就属于伪极简 |

## “排除在范围外”不等于“不重要”

这里最容易误解。

“把 correctness、security、performance 排除在这个专门的减法审查范围之外”**不是说它们不需要审查**，而是：

```text
减法审查不能据此宣称：
“代码更短了，所以它是正确、安全、高性能的。”
```

更准确的流程是：

```text
1. 正常 code review：
   检查功能正确性、测试、错误处理、安全、性能与可维护性。

2. 减法审查：
   在不破坏第 1 步结论的前提下，删除不必要的复杂度、
   重复说明、无关配置、过早抽象和额外认知负担。
```

也就是说，**减法审查的前提是“不能损伤关键属性”**，但它本身不负责证明这些关键属性成立。

## 为什么要刻意分开

因为“更少”与“更好”并不总是同义。

例如你在写一个 Python API：

```python
def get_user(user_id):
    return db.execute(f"SELECT * FROM users WHERE id = {user_id}").fetchone()
```

从“减法”视角，它比带参数绑定、权限检查、异常处理、输入验证的版本更短；但它可能有注入风险，也可能不符合授权需求。

所以减法审查可以提出：

- 这个额外的 `UserRepository` 抽象是否只包了一层、没有实际价值？
- 日志中重复输出同一份用户数据是否可以删掉？
- 三个近似的 helper 是否可以合并？
- CLI 输出中的背景说明是否可以压缩成一个明确命令？

但它**不能**提出：

- “删掉参数化查询，代码更简单”
- “删掉权限检查，调用路径更直接”
- “删掉超时、重试和错误处理，逻辑更短”
- “删掉数据库索引或缓存，因为实现更少”

这些“简化”碰触了 security、correctness 或 performance，应当由正常工程审查否决。

## 实际可用的审查提示词

你可以把这种边界写进自己的 Agent prompt：

```text
执行一次减法审查。

目标：识别可以删除、合并、延后或简化的代码、配置、
抽象、文档和输出，以降低维护与认知负担。

本轮不对 correctness、security、performance 作完整评估，
也不得为了“更少”而建议删除验证、错误处理、权限控制、
输入校验、测试、超时、资源限制或必要的性能保护措施。

对每项建议输出：
1. 可删除或可简化的对象
2. 删除理由
3. 预期收益
4. 必须保持不变的行为与安全边界
5. 建议通过哪些测试或常规 code review 检查确认
```

## 一句话记忆

- **正常 code review** 问：*“这是否正确、安全、可维护且足够快？”*
- **减法审查** 问：*“在不破坏上述条件的情况下，哪些东西根本不必存在？”*

后者是前者的补充，不是替代。
